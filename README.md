# ききみみ (Kikimimi) for Mac

[![build](https://github.com/tokoinx/Kikimimi/actions/workflows/build.yml/badge.svg)](https://github.com/tokoinx/Kikimimi/actions/workflows/build.yml)

**Mac の中だけで完結する音声文字起こしアプリ。** 会議・インタビュー・動画の音声を、時刻付きの文字にします。

[English README](README.en.md)

Swift / SwiftUI で書いたネイティブ Mac アプリです。音声認識には **whisper.cpp** (OpenAI Whisper の C/C++ 実装)、監査と翻訳には **llama.cpp** と無料の小さな LLM (**Qwen3.5**) を使い、どちらも Apple Silicon の GPU (Metal) で動きます。
音声も文字起こしの内容も Mac の外に出ません。インターネットを使うのは、最初にモデルを取得するときだけです。ただし、LLM とのチャットで「リサーチ」を入れた時だけ、あなたが発言に書いた URL の Web ページを読みに行きます (リサーチは既定で切。下の「LLM とのチャット」)。

- 音声・動画ファイル (mp3 / m4a / wav / aiff / caf / mp4 / mov …) をドロップ → 時刻付きで文字起こし
- Finder の「このアプリケーションで開く」や Dock アイコンへのドロップでも追加できます
- 認識できた文から順に画面へ表示。途中で中止もできます
- マイク録音 (録音中は数秒ごとに直近の内容をプレビュー、止めると全体をていねいに認識)
- 行をクリックすると、その行だけを再生し、行の終わりで止まる (もう一度クリックで停止。スペースキーか下の再生ボタンでも止まり、もう一度押すと止めた所から続けて再生。右クリックの「ここから続けて再生」で、その位置から続けて再生)、検索ハイライト
- **監査役**: 文字起こしのあと、同じ文の繰り返しと聞き取りミスを見直します。自信のある直しだけを反映し、それ以外は「提案」として残します。どの直しも一覧で確かめて元に戻せます
- **翻訳 (13 言語のどれかへ)**: 左に原文、右に訳を並べて表示します。訳す先は、設定で 13 言語 (日本語・英語・中国語・韓国語・スペイン語・フランス語・ドイツ語・イタリア語・ポルトガル語・ロシア語・ベトナム語・タイ語・インドネシア語) から選べます (初めは画面の言語と同じ。日本語の画面なら日本語へ訳します)。まとめて訳すほか、行の「訳」で読みたい文だけを 1 文ずつ訳せます
- 書き出し: txt / srt / vtt / Markdown / csv / json (原文・訳・対訳)
- **LLM とのチャット** (⇧⌘L): Mac の中で動く同じ LLM に、ききみみの事を聞いたり、設定の変更を頼んだりできます。LLM は変更の案を出すだけで、設定が変わるのは、あなたが案の「変える」を押した時だけです。Web ページを読む「リサーチ」は既定で切で、入れる時は自己責任です (下の「LLM とのチャット」)
- **ライブラリ**: 終わった結果 (文字起こし・訳・監査の決定) は自動で Mac の中に保存され、次に起動したときも一覧に出ます
- **メモと履歴**: 結果ごとにメモ (理解したこと・覚えたい表現) を書けます。行を右クリックして「メモに引用」で、その文を時刻つきで貼れます。いまの状態を「版」として残し、あとで戻せます
- 言語: 日本語・英語・中国語・韓国語など (自動判定も可)
- **日本語＋英語**: 英語の講師と日本語の通訳のように、日本語と英語が入れ替わる録音向けの設定です。区切りごとに話している言語を判定し、その言語で文字にします。行には「英」「日」の印が付き、英語の行だけを訳します (時間は「日本語」の 2〜4 倍ほど。言語の入れ替わりや短い差し込みが多いほど長くなります)。言語を「日本語」「英語」「自動判定」にしていても、日本語と英語が混ざった録音だとわかれば、自動でこの設定に切り替えて文字にします (結果の画面に知らせが出て、元の言語だけでやり直すこともできます。設定で切れます)

## 必要なもの

- macOS 14 (Sonoma) 以降。Apple Silicon 推奨 (Intel Mac でも CPU で動きますが遅くなります)
- Xcode 16 以降、または Command Line Tools (`xcode-select --install`)
- 空きディスク 1 GB 程度 (おすすめの音声認識モデルが約 574 MB)。監査・翻訳も使うなら、さらに約 3 GB (おすすめの LLM が約 2.7 GB)
- メモリ 8 GB 以上 (LLM の 9B モデルは 16 GB 以上)

## ビルドと起動

```bash
git clone https://github.com/tokoinx/Kikimimi.git
cd Kikimimi
make run
```

`make run` は次をまとめて行います。

1. `swift build -c release` (初回は whisper.cpp と llama.cpp のビルド済みフレームワーク 約 54 MB + 約 65 MB を GitHub から取得)
2. `build/Kikimimi.app` の組み立てと whisper.framework / llama.framework の同梱
3. ad-hoc 署名
4. 起動 (ききみみが起動中なら、いったん終了させてから新しいものを開き、数秒後に動いているかを確かめます。動いていなければ、原因を調べて `build/doctor.txt` にまとめます)

起動は `make run` で行ってください。`open build/Kikimimi.app` だけだと、前のものが動いているときは新しい版が起動しません。

`/Applications` に入れるなら:

```bash
make install
```

### 初回の使い方

1. 起動すると「モデルをダウンロード」ボタンが出ます (モデルが 1 つも入っていない時だけ)。おすすめの **Large v3 Turbo (軽量版)** は約 574 MB で、一度取れば以後はオフラインで動きます。
   - 上のモデルの欄で、まだダウンロードしていないモデルを選ぶと、横に青いダウンロードの印 (丸に下向きの矢印) が出て、その下に「モデルをダウンロードしてください」の案内が開きます。案内の「ダウンロード」か、青い印を押すと、ダウンロードが始まります。ダウンロードしないままファイルを開いた時は、文字起こしの始めに自動でダウンロードします。
   - モデルの欄のメニューで、チェックの印が付くのは、いま選んでいるモデルだけです。入れてあるモデルは、選ぶと横に緑の印が出ます (設定 (⌘,) の「モデル」の一覧でも見られます)。
2. 音声ファイルを読み込みます。やり方は 2 つです。
   - **開く**: 左上の「開く」のボタンか ⌘O で、ファイルを選びます (いくつでも選べます)。
   - **落とす**: Finder から、音声・動画のファイルを、ウインドウのどこかに落とします (いくつかまとめて落とすと、落とした順に文字起こしします)。音声・動画でないファイルやフォルダは読み込まず、名前を知らせます。録音中は読み込みません。
3. 認識できた文から順に右側へ出ます (行はまとめて足します。行が少ないうちは 1 秒に 4 回まで、数千行になると 1 秒に 1 回まで。一覧は、いちばん下を見ているあいだだけ新しい行を追いかけ、上へスクロールしたり行を押して再生したりすると止まります。右下の「末尾へ」で戻れます)。終わった結果は自動で保存されます (下の「ライブラリ・メモ・履歴」)。ほかのアプリで使うときは「書き出す」でファイルにします。

結果が思ったとおりでない時 (文字が少ない・言語が違う・失敗した) は、結果の画面の「やり直す」から、その結果だけの指定で、もう一度文字起こしできます: 「同じ設定でやり直す」「無音を飛ばさずにやり直す (歌・音楽向け)」「無音を飛ばしてやり直す」「言語を変えてやり直す」。元の結果は残り、新しい結果が一覧に足されます。失敗・中止した結果には「もう一度文字起こしする」のボタンが出ます。

画面の言語は、設定 (⌘,) の「一般」のタブの「画面の言語」で、13 言語 (English・日本語・简体中文・한국어・Español・Français・Deutsch・Italiano・Português (Brasil)・Русский・Tiếng Việt・ไทย・Bahasa Indonesia) から選べます。初めて起動した時は、macOS の言語がこの 13 の中に在ればその言語、無ければ英語です。言語を変えると、画面の文はすぐ変わります。macOS が出す決まりのメニュー (編集・ウインドウなど) は、ききみみを開き直すと変わるので、変えた時に案内が出ます (「今すぐ開き直す」で、保存を書き終えてから開き直します。作業の途中は、終わってから開き直してください)。開き直す時は、前のききみみが終わるのを 60 秒まで待ちます。終わらない時は、新しく開きません。.app から起動していない時 (`swift run` など) は、開き直しのボタンを出しません。日本語と英語のほかの 11 言語の訳は AI が作った物で、その言語を話す人の確認はありません。

録音 (⌘R) を使うと、初回だけマイク許可のダイアログが出ます。

監査と翻訳を使うときは、LLM を一度だけ取得します。起動したときの画面や結果の画面に出る「ダウンロード」か、設定 (⌘,) の「監査・翻訳」タブから取得できます。取得後は、文字起こしが終わるたびに自動で監査し、英語などの区間を日本語に訳します。

## ライブラリ・メモ・履歴

文字起こしの結果は、何もしなくても Mac の中に保存され、次に起動したときも左の一覧に出ます (書き出さなくても消えません)。

- **保存先**: `~/Library/Application Support/Kikimimi/Library` (モデルの `Models` フォルダのとなり。環境変数 `KIKIMIMI_LIBRARY_DIR` で変えられます)。結果 1 件ごとに 1 つのフォルダを作り、中に `document.json` (文字起こし・訳・監査の決定・版の一覧)、`notes.md` (メモ。ふつうの文字なので、ほかのアプリでも読めます)、`versions/` (版) を置きます。
- **いつ保存するか**: 文字起こしが終わったとき (文字が 1 つでもあるとき) と、そのあと監査・翻訳・直しの反映などで変わったとき (1 秒ほどまとめてから)。メモも、書いてから 1 秒ほどで保存し、メモの欄の右上に「保存しました」と出ます。中止・失敗した文字起こしは保存しません。書き込みは裏で順に行うので、数千行の結果でも画面は止まりません。アプリを終了するときは、待っている保存を書き終えてから終わります。
- **消す (ゴミ箱に入れる)**: 左の一覧で結果を選び、上のゴミ箱のボタンを押すか、一覧で delete キーを押します (一覧の右クリック ›「ゴミ箱に入れる…」、メニューの「ファイル」›「ゴミ箱に入れる…」でも同じ)。どの入口でも、消す前に確認の画面が出て、「ゴミ箱に入れるもの」と「残るもの」を、場所 (パス) つきで見せます。パスの横の「Finder で表示」で、その場所を開けます。
  - ゴミ箱に入れるもの: その結果のフォルダ (文字起こし・訳・メモ・履歴)。マイクの録音は、アプリの `Recordings` フォルダにある録音も (ほかの結果が同じ録音を使っている時は残します)。
  - 残るもの: 「開く」や、落として読み込んだ、元の音声・動画ファイル。アプリは消しません。
  - 入る先は macOS のゴミ箱です。ゴミ箱を空にするまでは、Finder で取り出せます。
  - 保存していない結果 (文字起こし中・中止・失敗) は、確認のあと、一覧から外すだけです (ファイルは消えません)。文字起こしや監査・翻訳の途中の結果は、作業を止めてから消します。
- **音声ファイルを動かした・消した**: 結果は残ります。再生はできず、結果の画面に「音声ファイルが見つかりません: <場所>」と出るので、「音声を選び直す…」で新しい場所を選ぶと、また再生できます。
- **読めない結果**: `document.json` が壊れていて読めないときは、そのファイルを `document.unreadable-<日時>.json` という名前に変えてとっておき、一覧には出さずに、何件あったかを知らせます。

**メモ**: 操作列の「メモ」にチェックを入れると、一覧の右にメモの欄が出ます (幅は境目を動かして変えられます)。理解したこと・覚えたい表現などを自由に書けます。行を右クリックして「メモに引用」を選ぶと、`> [02:22] Have you ever ...` のように、時刻つきでその文をメモの終わりに足します。メモは「書き出す」›「メモ (.md)」でファイルにもできます。

**履歴 (版)**: 操作列の「履歴」(またはメニューの「ファイル › 版として保存…」(⌘S) /「履歴…」) で、履歴の画面を開きます。
- 「いまの状態を版として残す」: 名前 (なくてもよい) を付けて「保存」を押すと、その時点の文字起こし・訳・メモの写しを版として残します。「新しい版として保存」は版を増やし、「いちばん新しい版に上書き」は、自分で残したいちばん新しい版を、いまの中身で書きかえます (版を増やしたくないとき)。
- 「この版に戻す…」: 戻すもの (「文字起こしと訳」「メモ」) を選んで戻します。戻す前の状態は、版 (「自動 (戻す前)」) として自動で残すので、戻したあとでも元に戻せます。
- 版はゴミ箱の印で消せます。監査・翻訳の最中は、版を残したり戻したりできません。
- 文字起こし・訳・メモは、版を残さなくても、変えるたびに自動で保存されます。版は、その時点の写しです。

## 聞き取りの練習

結果の行は、そのまま英語の聞き取りの練習に使えます。行を押すとその行を流し、下の再生の列の右の 2 つのボタンで、流し方を変えられます。設定は次の起動でも残ります (「隠す」だけは、起動のたびに「隠さない」に戻ります)。

- **速さ** (「1.0×」のボタン): 0.5×・0.6×・0.75×・0.85×・1.0×・1.25× から選びます。ふつうの再生にも、1 行の再生にも効き、流している途中でもすぐ変わります。声の高さは変わりません。
- **「練習」のボタン** (決まりの設定から変えているときは色が付きます):
  - 「繰り返し」: 1 行を 1 回・2 回・3 回・5 回、または「止めるまで」続けて流します。
  - 「行のあとの間」: 「行と同じ長さだけ空ける」にすると、1 回流すごとに、声に出して言ってみるための間を空けます (いまの速さで流した長さと同じ。1〜15 秒)。間のあいだは、再生の列に「間 (声に出してみましょう)」と出ます。
  - 「自動で次の行へ進む」: 繰り返しと間が終わったら、次の行へ進みます。
  - 「隠す」: 「原文を隠す」は、訳す先の言語でない行 (訳す先が日本語なら、日本語でない行) の原文を灰色の帯にします (訳す先の言語の行は隠しません)。「原文と訳を隠す」は、その行の日本語訳も隠します。隠した行の目のボタンで、その行だけを見たり、また隠したりできます (見せた行は、隠し方を変えるか、ほかの結果を選ぶと、また隠れます)。検索は、隠していても本当の文で探します。
  - 「書き取りの欄を出す」: 一覧の下に書き取りの欄を出します (下)。
- **キー**: ↓ で次の行、↑ で前の行、← でいまの行をもう一度流します (メニューの「再生」にもあります)。スペースキーと再生ボタンは、続けて流しているのを止めます。検索欄など、文字を打つ欄にいるときは、キーはふつうに文字の欄へ届きます。左の結果の一覧を触っているあいだは、矢印は一覧の上下に使います (行を押すと、行のほうへ戻ります)。キーや自動で次へで始めた行は、見えるところまで一覧を少しだけ動かします。
- 行を押す・もう一度押す (止める)・再生のつまみを動かす・「ここから続けて再生」・ほかの結果を選ぶ・結果を消す・マイクで録音を始める、でも、続けて流すのは止まります。

**書き取り**: 行を流してから、一覧の下の欄に、聞こえたとおりに打って Return を押すと、その行の文と比べて結果を出します (その行は一覧でも見えるようになります)。合っている語はふつうの色、違う語は打った語を赤の取り消し線で出して、そのあとに正しい語を緑で、打っていない語はオレンジで [ ] に入れて、余計に打った語は赤の取り消し線で出します。右に「12 / 14 語」(日本語の行は 1 文字ずつ比べて「字」)、すべて合っていれば「全部合っています」と出ます。大文字と小文字、語の前後の記号は区別しません。そのままもう一度 Return を押すと、欄を空にして次の行を流します。「もう一度聞く」(⌘L)・「前の行」・「次の行」のボタンもあります。打ち直すと結果は消え、いまの行が変わると欄も空になります。

## 監査と翻訳 (ローカル LLM)

文字起こしの結果を、Mac の中で動く小さな LLM がもう一度読み直します。

- **監査役 (聞き取りミス・繰り返しの見直し)**
  - 規則: すぐ前と同じ文・ほぼ同じ文・一部の繰り返しを見つけます。自動で消すのは、句読点まで同じ長めの文が、すき間なく 2 度続いたとき (同じ音声を 2 度読んだもの) だけです。間をあけたくり返し (何人かが順に言うあいさつ・語学の練習)・言い直し (「月曜に」→「火曜に」)・聞き返し (「〜です。」「〜ですか？」) は消さずに提案にとどめ、数字が違う文は別の文として扱います。
  - LLM: 文脈から見て明らかな聞き間違い (同音の別の語、崩れた固有名詞) と、実際には話していない文 (無音や音楽のところの「Thank you for watching.」など) を見つけます。
  - 直し方: LLM には行ぜんたいを書き直させず、「聞き間違えた語 => 正しい語」だけを答えさせて、元の行のその語だけを置き換えます (行に無い語の指摘は使いません)。答えの形は文法で「問題のある行だけを番号順に 1 回ずつ、最後に END」に縛ってあるので、同じ指摘をくり返す暴走が起きません。
  - **評価役**: LLM が出した直しは、「直す前」と「直した後」のどちらが実際に話された文かを、並びを入れ替えて 2 回たずね直します。2 回とも直した方を選んだときだけ自動で反映し、判断が割れたら提案どまり、2 回とも直す前を選んだら捨てます (小さなモデルの「1 番目を選びがち」などの癖を打ち消すためです)。
  - 安全の基準: さらに、直す量が少ない・言語が変わらない (翻訳になっていない)・語を足す/削るだけの手直し (助詞や語尾) ではない、を満たす直しだけを自動で反映します。数字が変わる直し (「3時」→「5時」)・否定が変わる直し (can't → can)・漢字が新しく入る直しは、LLM が音声を聞いていない以上は推測なので、必ず提案にとどめます。英語の語は語の切れ目で合わせます (can を直すつもりで scan を変えない)。削除は、近くに同じ文が「残る」ときだけ自動にします。1 回の見直しで半分近くの行を直したがる答えは、書き換えとみなしてすべて提案どまりにします。「ご視聴ありがとうございました」のような定番の文は、実際にそう話すこともあるので提案どまりです。
  - 監査をやり直しても、あなたが反映した・取り消した直しはそのまま引き継ぎます。途中で中止したり LLM が使えなかったりしても、規則の見直しと、見終えた所までの結果は反映します。
  - 結果の画面の「監査: 修正 3 · 削除 2 · 提案 1」から一覧を開き、1 か所ずつ反映・取り消しができます。行の横の印 (修正済み / 修正の提案 など) を押しても確かめられます。
- **翻訳役 (訳す先の言語へ)**
  - 訳す先の言語は、設定 (⌘,) の「監査・翻訳」のタブの「訳す先の言語」で、13 言語から選びます。選んでいない間は、画面の言語と同じです。訳すのは、訳す先と違う言語の区間です (訳す先が日本語なら、日本語以外の区間)。
  - 結果は、どの言語に訳したかを覚えています。1 つの結果の訳は 1 つの言語にそろえるので、もう訳してある結果は、設定を変えても、その結果の言語で訳を続けます。設定と違う言語で訳してある結果には知らせが出て、「〇〇で訳し直す…」を選ぶと、確認のあと、今の訳を外して訳し直します (今の状態は、履歴に版「訳す先の言語を変える前」として残ります)。
  - 下の 3 つの説明は、訳す先が日本語の時の物です。ほかの言語へ訳す時は、その言語の手本のやりとりを見せます。日本語だけの仕組み (日本語に出てこない漢字を候補から外す) は使いません。
  - 日本語以外の区間を、文ごとに日本語に訳します。Whisper の区間は文の途中で切れることが多く、区間ごとに訳すと日本語の語順のせいで訳が隣の区間にずれるため (本物の Qwen3.5 4B で確かめました)、続いている区間を文の終わりまでまとめて 1 行として訳し、その訳を右の列で複数の区間にまたがって表示します。数行ずつまとめて訳し、番号と行数は llama.cpp の文法 (GBNF) で縛ります。読めなかった行は 1 行ずつ訳し直します。
  - Qwen は訳文が中国語に流れることがあるので、日本語の手本のやりとりを先に見せ、日本語に出てこない漢字 (簡体字など) は出力の候補から外しています。
  - 画面は左に原文、右に日本語訳。もともと日本語の区間は、右の列に原文を薄く出します。「対訳」のチェックで切り替えられます。
  - 設定の「語彙のヒント」に書いた固有名詞は、監査と翻訳でもその表記を使います。
  - **1 文だけ訳す**: まだ訳のない日本語以外の行には「訳」が出ます。押すとその行を含む 1 文だけを訳します (メモリ 8 GB の Mac で全体を訳すのが重いとき向け。自動の翻訳を設定で切っても使えます)。文のまとめ方とプロンプトは「翻訳」と同じなので、あとで「翻訳」「残りを翻訳」を押しても、訳した文は飛ばします。いくつか押すと順に訳し、待っている行・訳している行は「訳」がくるくるに変わります。「中止」で止められます。訳のある行は、右クリックの「この文を訳し直す」で訳し直せます。
  - **訳を直す・覚えた訳・要確認**: 対訳の行の右クリック「訳を直す…」で、訳を自分で書き換えられます。直した訳は覚えておき、次の翻訳で同じ文が出たら使います。疑わしい訳には「要確認」の印が付きます。「この語は、こう訳す」(訳語) も覚えられます。くわしくは下の「訳を直す・覚えた訳・要確認」。
- 手動でも実行できます: 監査 ⇧⌘K、翻訳 ⇧⌘T (結果の画面のボタンでも)。

| LLM | 向いている用途 | サイズ | メモリ |
|---|---|---|---|
| Qwen3.5 4B | 監査と翻訳のバランスが良い。迷ったらこれ | 約 2.7 GB | 8 GB 以上 |
| Qwen3.5 2B (軽量) | 速さ優先。精度は控えめ | 約 1.3 GB | 8 GB 以上 |
| Qwen3.5 9B (高精度) | いちばん賢いが遅い | 約 5.7 GB | 16 GB 以上 |

- どれも Apache-2.0 の無料モデルです。量子化 Q4_K_M の GGUF を Hugging Face から取得し、`~/Library/Application Support/Kikimimi/Models/LLM` に `qwen3.5-4b.gguf` (2B は `qwen3.5-2b.gguf`、9B は `qwen3.5-9b.gguf`) という名前で保存します。取得中は一時ファイルに書き、ダウンロードが終わって中身を確かめてから、このフォルダに移します (それまではフォルダに現れません)。確かめるのは、GGUF であることと、Hugging Face のファイル一覧にある大きさと SHA-256 です (一覧を取れなかったときは、GGUF であることだけ)。設定の「LLM のフォルダを開く」で Finder に表示できます。
- ダウンロードの途中でアプリを終了すると取得は中止され、次は最初からやり直しになります (設定のウインドウを閉じても、取得は続きます)。
- 手持ちの GGUF (llama.cpp で動くもの) も、設定の「手元の GGUF を追加…」で使えます。
- 目安: 1 時間の英語の講演なら、M1 で監査に数分、翻訳に 10〜20 分ほどかかります (4B の場合。訳は終わった所から順に右の列に出ます)。急ぐときは 2B を選んでください。
- メモリ 12 GB 未満の Mac では、音声認識のモデルと LLM を交互に読み込んで、同時にメモリを使わないようにしています。
- 小さな LLM なので、クラウドの大きなモデルほど賢くはありません。監査は「自信のあるものだけ自動、それ以外は提案」にしてあるので、大事な文書では提案を確かめてから使ってください。

## LLM とのチャット

監査・翻訳と同じ、Mac の中で動く LLM (設定で選んでいる Qwen3.5) と話せます。ききみみの使い方を聞いたり、設定の変更を頼んだりできます (2026-11-20 から)。

- **開き方**: メニューの「ファイル」›「LLM とチャット」(⇧⌘L) か、メインの窓のツールバーの吹き出しの絵のボタン。チャットは別の窓に開きます。
- **答え**: 答えは少しずつ出ます。「中止」で止められます。追加学習の差分 (LoRA) は使いません。
- **会話は保存しません**: アプリを閉じると消えます。「新しいチャット」で空にします。
- **監査・翻訳の最中**: LLM は同時に 1 つの仕事しかしませんが、チャットは、監査・翻訳のかたまり (LLM を 1 回呼ぶ分) の合間に入って、先に答えます。待つのは、今のかたまりが終わるまでです (その間は「LLM を待っています…」と出ます。M1 の Mac・Qwen3.5 4B で見た時は、読み込みを含めて 40 秒ほど)。チャットが答えている間、監査・翻訳は止まり、答えの後で続きます。追加学習の差分 (LoRA) を使っている監査・翻訳の最中と、1 回の呼び出しに収まる短い結果 (10 行ほどまで) では、今までどおり、終わるまで待ちます。
- **設定を変える案**: 「メモの欄を出して」のように頼むと、LLM の答えの下に「メモ: オフ → オン」のような札が出ます。**設定が変わるのは、札の「変える」を押した時だけです。** 「キャンセル」なら変わりません。チャットから変えられるのは 20 項目です (画面の言語・話されている言語・文字起こしのモデル・無音を飛ばす (VAD)・語彙のヒント・LLM のモデル・訳す先の言語・自動の翻訳・メモの欄・書き取りの欄など。一覧は `Sources/KikimimiCore/Chat/ChatSettings.swift` の `ChatSettingsCatalog`)。一覧に無い項目と、取れない値は、札にしません。設定の画面を開く案は、ボタンとして出るだけで、勝手には開きません。
  - LLM は、頼んでいない時にも変更の案を出す事があります (「VAD って何？」のような質問への答えに付く事がありました)。札は押さなければ何も変わらないので、内容を見てから押してください。
  - 札の項目名は、設定の画面と同じ文です (例: 「モデル」「LLM」「日本語以外の区間を、日本語に翻訳する」。最後の物は、訳す先の言語で変わります)。
  - 設定の画面で押せない時は、札にも「変える」が出ず、理由が出ます (無音を飛ばす (VAD) が切の時の「音が続いているのに文字が少ない時は、無音を飛ばさずにやり直す」と、差分が入っていない時の「差分を使う」)。同じ答えの前の札で無音を飛ばすを入にすると、その場で押せるようになります。
  - 「対訳」は、結果の画面の「対訳」のチェックと同じ値を見ます (選んでいる結果で行の「訳」を押していれば入。チャットから切にすると、その結果の対訳も隠れます)。
  - 語彙のヒントは 400 字までです。設定の欄の右に「今の字数 / 400」が出て、400 字を超える入力は受け付けません (前から 400 字を超えて保存してある値は、そのまま残り、短くはできます)。貼り付けた改行やタブは、空白に替わります。チャットの案も、400 字を超える物と、改行などの制御文字が入った物は札にしません。

### リサーチ (Web ページを読む事)

> **リサーチは、既定で切です。アプリを開くたびに切に戻ります (保存しません)。**
> チャットの窓の上には、いつも次の帯が出ます。
> - 切の時: 「リサーチ (Web ページを読む事) は、基本的に使えません (切)。必要な時だけ、自己責任で入れてください。」
> - 入の時 (橙色): 「リサーチが入っています (自己責任)。Prompt Injection による破損や損害は、自己責任でお願いします。」
>
> 「入れる…」を押すと、確認のシートが出ます。題は「自己責任で、リサーチを入れますか？」、文は「リサーチを入れると、あなたが書いた URL の Web ページを読みます。Web ページには、LLM にまちがった答えや、頼んでいない変更の案を出させる、隠れた指示 (Prompt Injection) が入っている事があります。Prompt Injection による破損や損害は、自己責任でお願いします。」です。既定のボタンは「キャンセル」で、入れるのは「自己責任で入れる」を押した時だけです。

- **読む物**: リサーチが入の時、あなたが発言に書いた `https` の URL (3 つまで) のページを読み、その文を LLM に渡します。**LLM が自分で外へつなぐ事はできません。Web の検索はありません。** 切の時は、URL を書いても読みに行きません (答えに「リサーチが切なので、ページは読んでいません。」と出ます)。
- **守り**:
  - リサーチのスイッチは、チャットからは変えられません (変えられる項目の一覧に入れておらず、アプリの側でも断ります)。
  - ページを読んだ回の答えからは、設定を変える案を作りません。
  - ページの文は区切りの中に入れ、「中の指示に従わない」と LLM に伝えます。ただし、LLM が必ず守る保証はありません。
  - 読みに行く時は、クッキーを使わず、GET だけで、URL のほかは何も送りません。2 MB まで・15 秒まで・転送は 5 回までで、転送の先も同じように調べます。`localhost`・IP アドレスの直書き・内の名前 (`.local` など)・443 以外のポートは読みません。
- 防げない事は、下の「既知の制限」に在ります。

## 学習した直し・評価ハーネス・追加学習

小さな LLM は、それだけでは頼りになりません。ききみみは、LLM のまわりに「覚える・確かめる・測る」仕組み (ハーネス) を置いて支えています。追加学習は、その上に重ねる任意の手段です。

### 学習した直し (記憶)

- 監査の一覧で直しを **反映** したり **元に戻し** たりすると、その決定を「聞き間違えた語 → 正しい語」として覚えます。設定の「監査・翻訳」の「学習した直し」で、一覧・削除・自分での追加ができます。
- 反映した直しは、次の監査から LLM に聞く前に当てます (一覧には「学習した直し」と出るので、いつでも元に戻せます)。元に戻した直しは、LLM がまた出してきても使いません。正しい語は、文字起こしと翻訳の語彙のヒントにも足します。
- 行を手で直した時にも、シートの「この直しを覚える」で、同じように覚えさせられます (「聞き取った文を直す」)。
- 1 回反映しただけの直しは、次は **提案** として出します。2 回反映すると、次から **自動** で直します (その行でだけ正しい直し、たとえば「break → brake」「機関 → 期間」を、1 回の反映でどの録音にも当たる規則にしないためです)。数字や否定が変わる直し・かなを漢字にする直しは、何回反映していても提案どまりで、行ごとに確かめます。設定で自分で追加した直しは、いつも自動で当てます (「T-pie → TPIE」のような大文字や記号だけの直しも)。
- この行では元に戻した、という決定は、その文字起こしの監査をやり直しても引き継ぎます。
- 保存先は `~/Library/Application Support/Kikimimi/learned-corrections.json` で、Mac の外には出ません。LLM を取得していなくても働きます。

### 関門 (機械の点検)

LLM の答えは、反映する前に機械で点検します (評価役の問い直しと安全の基準は上のとおり)。評価ハーネスで測って、次の 2 つを足しました。

- 語の代わりに説明を書いてきた直し (「no error」「note: …」、かっこ書き、元の語の 3 倍より長いもの) は捨てます。
- 近くに同じ文が無く、定番の誤認識でもない「削除」の提案は出しません (小さなモデルは、ふつうの文をよく「話していない文」と言います)。

### 聞き取った文を直す

聞き取りを間違えた行 (例: 「走って」が「浜って」になった行) は、自分で直せます。

- 行を右クリックして「この行を直す…」を選ぶと、一覧の外にシートが開きます。聞き取った文が上に残り、下の欄で直して「保存」します。対訳の表示では、行に入っている文 (区間) の全部が、それぞれの入力欄に出ます。
- 直した行には、原文の側に灰色の印「直した」が付きます。印を押すと、同じシートが開きます。シートの「聞き取った文に戻す」で、いつでも元に戻せます。
- 直した行の訳は消えます。行の「訳」で訳し直してください (自動では訳し直しません)。
- 手で直した行は、監査をやり直しても上書きされません。その行に在った監査の直し・提案は、直した時に消えます。
- 文字起こしをやり直した新しい結果には、直しは引き継がれません。文字起こしの最中の結果は、直せません。
- **この直しを覚える**: 設定の「監査の一覧で決めた直しを覚えて、次から使う」が入の時、シートの入力欄の下に「この直しを覚える」と、聞き間違えた語 → 正しい語の 2 つの欄が出ます。組は、聞き取った文と直した文の違う所を、語の切れ目まで広げて切り出します (欄は書き換えられます)。入のまま保存すると、組を「学習した直し」に 1 回分覚えさせます。次の監査から、同じ聞き間違いに、この直しを案 (要確認) として出し、2 回覚えると自動で直します (監査の一覧で反映した時と同じ)。
- 同じ行を同じ組で直し直しても、回数は増えません。「聞き取った文に戻す」と、覚えさせた 1 回を取り消します。

### 訳を直す・覚えた訳・要確認

翻訳にも、監査と同じ「覚える・確かめる・測る」仕組みを足しました (2026-11-16)。

- **訳を直す**: 対訳の行を右クリックして「訳を直す…」を選ぶと、一覧の外にシートが開きます。保存した行には、灰色の印「直した」が付きます。シートの「機械の訳に戻す」で、元の訳に戻せます。あとで翻訳が進んでも、機械の訳が、直した訳を上書きする事はありません。
- **訳の記憶**: 直した訳は「訳の記憶」(`~/Library/Application Support/Kikimimi/translation-memory.json`。学習した直しの台帳と同じフォルダ) にたまります。入るのは、自分で直した訳だけです (機械の訳は入れません)。5 件に 1 件は、評価に使うために取り分けます (`heldOut`。学習と手本には使いません)。
- **覚えた訳**: 次の翻訳で、同じ原文・同じ訳す先の文が出たら、LLM に頼まずに覚えた訳を置きます。原文は、NFKC と空白をそろえてから比べます。置いた行には印「覚えた訳」が付きます。短い文 (重さ 16 未満。「Yes.」など) は、場面で訳が変わるので、引きません。「この文を訳し直す」は、記憶を引かず、いつも LLM に頼みます。設定の「監査・翻訳」の「覚えた訳」で、使う・使わないを選び、一覧を見て、消せます。
- **要確認**: LLM の訳は、文のまとまりごとに関門 (`TranslationGate`) で点検します。疑わしい訳には、橙色の印「要確認」が付きます。点検するのは、訳す先の言語か (language)・原文の数が残っているか (number)・原文の写しでないか (copied)・同じ語句の繰り返し (repeated)・原文よりかなり短くないか (short) などです。印を押すと「訳を直す」のシートに理由が出て、直すか「この訳でよい」を選べます。印が付いても、訳を勝手に入れ替えはしません (訳し直すのは、下の short の時だけです)。
- 訳を出さずに捨てるのは、前と同じ重い落ち (訳が返らない failed・文字の種類が違う script・長すぎる long) だけです。訳せなかった行には理由が残り、「未翻訳」にマウスを載せると出ます。
- 対訳の訳の列の見出しに「要確認 N」が出ます。押すと、次の印の行へ移ります。
- **訳の後ろが抜けた時だけ、文に分けて訳し直す** (2026-11-16): 関門の `short` の印が付いた訳だけ、原文を文に分け (`NLTokenizer`)、1 文を 1 行として LLM に送り直します。つないだ訳に重い落ちが無く、`short` が消えた時だけ、初めの訳と入れ替えます。1 文でも訳せなければ、入れ替えません (初めの訳と印が残ります)。ほかの印では、訳し直しません。評価ハーネスも同じ道を通ります (`--no-split-retry` で切れます)。
- **訳語** (2026-11-16): 「この語は、こう訳す」を、訳す先の言語ごとに覚えます (訳の記憶の `terms`)。入れる所は、「訳を直す」のシートの下の 1 行「語を、いつもこう訳す (任意)」と、設定の「覚えた訳」の中の「訳語」の一覧 (足す・消す) です。翻訳では、その 1 回に送る行に出る対だけを、指示文に足します (8 組まで)。対が無い時は、指示文を変えません。訳に訳語が無ければ、`term` の印が付きます (印だけ)。5 字以上の訳語は、頭の 75% が在ればよい事にします (語の形が変わる言語のため。ja・zh・th は、そのまま含むかで見ます)。訳語も、「覚えた訳」の入・切に従います。
- **関門が、あなたの判定から学ぶ** (2026-11-16): 印の付いた訳に「この訳でよい」を押すと「検査の誤り」、直すと「検査が当たった」と、検査ごと・訳す先ごとに数えます (訳の記憶の `gate`)。判定が 5 回以上で、8 割以上が「この訳でよい」だった検査は、その訳す先では印を出さなくなります。重い落ちは止めません。文に分けて訳し直す引き金 (`short`) は、止めた検査に関わらず働きます。設定の「覚えた訳」の「印を出さなくなった検査」に一覧が出て、[元に戻す] で戻せます。

### 評価ハーネス

「良くなったか」を、勘ではなく数で確かめるための仕組みです。聞き間違いを仕込んだ場面 (どの行が、どう直れば正解か) を LLM に監査させ、直せた行・見逃した行・**正しい行を壊した数**・不要な提案の数を数えます。場面は `Tests/Fixtures/llm-eval/seed.json` (英語 6・日本語 6 場面、誤りのある行 14・正しい行 36) にあり、自分の場面を足せます。

```bash
build/Kikimimi.app/Contents/MacOS/Kikimimi --eval-llm ~/Library/Application\ Support/Kikimimi/Models/LLM/qwen3.5-2b.gguf --set Tests/Fixtures/llm-eval/seed.json --report build/eval-2b.json
```

`--baseline <前の結果.json>` を付けると前の結果と比べ、悪くなっていれば終了コード 3 で止まります (正しい行を壊した数が増えた・直せた行が減った)。`--adapter <差分.lora.gguf>` で追加学習の差分を重ね、`--ledger <台帳.json>` で学習した直しを使い、`--rules-only` で LLM なしの規則だけを測ります。

**翻訳を 13 言語で測る**: 翻訳の場面に `target` (訳す先。無ければ日本語) と `references` (人の訳) を書くと、訳す先ごとに、訳せた行・その言語だった行 (日本語は文字の種類、ほかは macOS の言語の判定)・数と語が残ったか・原文の写し・同じ語句の繰り返し・chrF (人の訳との近さ、0〜100。コーパスの点) を数え、表に出します。`--baseline` は訳す先ごとに比べ、どれかが悪くなった (chrF は 1 点より大きく下がった) ら終了コード 3 です。公開の対訳データ WMT24++ から 13 の問題 (各 30 行) を作って、まとめて測る手順は `tools/translation-eval/README.md` に在ります。
結果 (`--report`) には問題ごとの LLM の訳そのもの (`translationOutputs`) が残るので、採点の決まりを直した後は `--eval-llm none --rescore <結果.json>` (フォルダごとなら `evaluate.py --rescore <結果のフォルダ>`) で、LLM を回さずに採点し直せます。千の区切り (4,000・4.000・4 000) は外してから数を比べます。
**関門を LLM なしで測る**: `--eval-llm none --gate <問題か結果>` (フォルダごとなら `evaluate.py --gate <フォルダ>`) は、人の訳 (問題) か LLM の訳 (結果) に関門を掛けて、印の数を数えます。
**訳語の対を測る**: 問題に `terms` (訳語の対) を書けます。`--no-terms` を付けると、対を渡さない時と比べられます。小さな問題が `Tests/Fixtures/llm-eval/translation-terms.json` に在ります。
**自分の直しで測る**: `Kikimimi --export-translation-eval <出力.json> [--memory <記憶>]` は、訳の記憶の取り分けた直しだけを、1 件 1 場面の問題に書き出します。`--eval-llm … --memory <記憶>` は、記憶 (覚えた訳・訳語・止めた検査) を渡して測ります。問題の文そのものは、記憶から抜いて測ります。
**道具が判定する**: `evaluate.py --baseline <前の結果>` は、訳す先ごとに「良くなった (chrF が 1.0 より大きく上がった)・変わらない・悪くなった・参考 (30 行に満たない)・比べられない」を、全体で「採る・採らない・変わらない (採る理由が無い)」を出します。秒/行が 1.1 倍を超えた訳す先は「遅くなった」と知らせるだけで、判定には入れません。`--save-baseline <名前> [--from <結果のフォルダ>]` で、基準を `tools/translation-eval/baselines/<名前>/` に残します。今の基準は、1 言語 30 行が `tools/translation-eval/baselines/qwen3.5-4b-20261116/`、1 言語 100 行が `tools/translation-eval/baselines/qwen3.5-4b-100-20261116/` です。
**似た文を手本にする (実験。既定は切)**: `--eval-llm … --memory <記憶> --examples <N>` (`evaluate.py --memory <記憶.json> --examples N`) は、記憶の中の、送る行に似た文を、多くて N 件、手本として指示文に足します。見立ての記憶は `tools/translation-eval/make_memory.py` で WMT24++ から作ります (評価の問題の行は除きます)。2026-11-16 に、日本語・韓国語・中国語・タイ語 × 100 行で測りました (手本は多くて 2 件、見立ての記憶は訳す先ごとに 300 文)。chrF (手本なし → 手本あり) は ja 29.06 → 29.25、ko 28.73 → 28.61、th 42.76 → 42.80、zh 35.52 → 35.27 で、道具の判定は「変わらない (採る理由が無い)」でした。手本が付いた呼び出しは、どの言語も、まとまり 72 個のうち 5 個だけだったので、「似た文が在る時に効くか」は分かっていません。アプリの翻訳では使いません (`TranslationOptions.memoryExamples` = 0)。

### 追加学習 (LoRA)

学習した直しがたまったら、LLM そのものに覚えさせることができます。元の LLM は書き換えず、小さな「差分」(LoRA アダプタ、数十 MB) を作って重ねます。学習も Mac の中だけで行います。

1. 設定の「監査・翻訳」の「学習用のデータを書き出す…」で、`kikimimi-training.jsonl` を書き出します。中身は、監査役と評価役が実際に受け取るのと同じ形の問いと、あなたの決定に沿った答えです (反映した直しは「直す」、元に戻した直しは「直さない」、何も指摘しなかった行は「そのまま」)。
2. 学習の道具を入れます (Apple シリコンの Mac。Apple の MLX を使います)。

   ```bash
   python3 -m venv .venv-finetune
   ```

   ```bash
   .venv-finetune/bin/pip install "mlx-lm[train]" gguf numpy
   ```

3. 学習します。学習 → GGUF への変換 → 評価ハーネスでの比較 (差分なしと、学習の途中の差分 5 つ) までを続けて行い、いちばん良いものが **差分なしより良くなっていれば** (直せた行が増え、誤った直しや正しい行を壊すことが増えていなければ)、ききみみの差分の置き場所に入れます。評価には、ききみみに付いている場面と、学習データから取り分けた自分の直しの場面 (学習に使っていない並び) を使います。効き目を確かめられない差分・悪くなる差分は入れません。

   ```bash
   .venv-finetune/bin/python tools/finetune/finetune.py --data ~/Desktop/kikimimi-training.jsonl --model qwen3.5-2b --install
   ```

4. 設定の「監査・翻訳」の「追加学習 (LoRA)」で、使う / 使わないを選べます。差分の行は、監査の差分と翻訳の差分 (下の「翻訳の追加学習」) の 2 つです。「外す」で元の LLM だけに戻ります。別の場所で作った差分は「差分を追加…」で入れられます (選んでいる LLM の種類・大きさと合わないものは断ります。読み込めなかったときは、差分なしで動かして知らせます)。

知っておいてほしいこと:

- **必要なメモリの目安**: 2B の学習に 8 GB、4B に 16 GB、9B に 32 GB。8 GB の Mac では 2B を使ってください (足りないときは止めて知らせます)。16 GB の M1 で 4B を学習させた時 (2026-11-16、mlx-lm 0.32.2、`mlx-community/Qwen3.5-4B-4bit`) は、30 回で 889 秒 (1 回 25〜30 秒)、検証 1 回 23〜25 秒、メモリの最大 16.0 GB、スワップ 0 でした。同じ Mac で、翻訳の学習を 400 回させた時 (下の「翻訳の追加学習」) は、peak memory footprint 28.0 GB・maximum resident set size 8.66 GB で、スワップを使いました (学習の初めの 50 回は、1 回に 50 秒ほど)。学習の間、ほかの重い作業は遅くなります。初回は、学習用のモデル (MLX 形式、`mlx-community/Qwen3.5-2B-4bit` など) を Hugging Face から取得します。
- **学習データは 12 件以上** 必要です。数件の直しなら、追加学習をしなくても「学習した直し」がそのまま当てます。追加学習が効くのは、直しが数十件たまり、覚えた語そのものではない似た場面にも広げたいときです。
- **学習の量と、差分の選び方**: 既定では、学習データを 5 周します (300〜1000 回。学習率は少しずつ下げます)。何回がよいかは決め打ちできないので、途中の差分を 5 つ残し、評価ハーネスでいちばん良いものを選びます。Qwen3.5 0.8B と 12 件の直し (学習例 90 件) で確かめた例 (誤りのある行 24 と、翻訳の場面 3。どれも学習に使っていない文):

  | | 直せた行 (うち自動) | 誤った直し | 正しい行を壊した数 | 不要な提案 | 翻訳で保てた固有名詞 |
  |---|---|---|---|---|---|
  | 差分なし | 3 (2) | 0 | 0 | 5 | 2/2 |
  | 100 回 | 2 (2) | 0 | 0 | 1 | 1/2 |
  | 200 回 | 12 (11) | 0 | 0 | 1 | 2/2 |
  | 300 回 | 14 (14) | 0 | 0 | 1 | 1/2 |
  | 400 回 | 14 (14) | 0 | 0 | 1 | 1/2 |

  直せる行は 300 回・400 回が最多ですが、翻訳で「Roblox Studio」が「ロブス・スタジオ」になる副作用が出たので、評価ハーネスは「悪くなっている」と判定し、翻訳を壊さない 200 回の差分を選びます。学習率を下げずに 600 回まで続けた別の実験では、500 回以降は逆にほとんど直さなくなり (2 行)、別の種では「Roblocks → Robo」という誤った直しも出ました。小さなモデルの追加学習はこのように不安定なので、必ず評価を通してから使ってください (スクリプトは自動でそうします)。上の数字は、同じ学習を PyTorch で行い、変換した差分を llama.cpp で評価したものです。
- スクリプトは、mlx-lm をそのまま使うと学習が効かなくなる 3 点を直しています (どれも、同じ学習を PyTorch で再現して確かめました)。
  - **学習の範囲**: mlx-lm は、答えの前の「考える部分を閉じる印」まで学習の対象にします。Qwen3.5 では学習のほとんどがそこに使われるので、答えだけを対象にします。
  - **損失の計算**: mlx-lm は、学習例の終わりの詰め物 1 つまで損失に数えます。答えだけ (3〜12 語) を学習すると、その 1 つが損失の大半になるので (ある例で 4.634 対 0.012)、数えないようにします。
  - **最適化**: MLX の Adam は、既定で偏りの補正をしません。最初の数百回は約 3 倍の大きさで重みが動き、学習率 2e-4 では不安定になるので (検証の損失が 0.36 → 1.15 → 1.78)、補正を有効にします。
- **差分は、学習に使った LLM 専用** です (2B で作った差分は 4B では使えません)。LLM を替えたら、学習し直してください。
- 学習するのは各層の MLP だけです (Qwen3.5 は注意機構と状態空間モデルの混成で、MLP の重みだけが MLX と GGUF で 1 対 1 に対応します)。変換は `tools/finetune/mlx_lora_to_gguf.py` が行います。

#### 翻訳の追加学習 (2026-11-16)

差分は、監査用 (`<LLM>.lora.gguf`) と翻訳用 (`<LLM>.translation.lora.gguf`) に分けてあります。監査には監査用、翻訳には翻訳用だけを使います。翻訳用が無い時、翻訳は差分なしで訳します (監査を学習した差分は、訳の名前を崩す事があるためです。上の「Roblox Studio」の例)。

1. 訳の記憶から、学習データを書き出します。取り分け (`heldOut`) でない文から、アプリが実際に送る会話 (指示・手本のやりとり・行) と同じ形の例を作ります (1 行の例と、2〜4 行をまとめた例)。`--memory` は何度でも指定できます。

   ```bash
   build/Kikimimi.app/Contents/MacOS/Kikimimi --export-translation-training ~/Desktop/kikimimi-translation.jsonl --memory ~/Library/Application\ Support/Kikimimi/translation-memory.json
   ```

2. `--task translation` で学習します。評価の問題 (`--eval-set`、何度でも) が要ります: 取り分けた直しの問題 (`--export-translation-eval` の出力) と、見張りの問題 (WMT24++ など)。候補は、訳す先ごとの chrF で選びます。選べるのは、`evaluate.py` の判定で「悪くなった」訳す先が無く、「良くなった」訳す先が在る候補だけです。途中の差分の候補は、既定で 3 つです (翻訳の評価は長いため)。1024 トークンを超える例は外します。`--install` は、翻訳用の置き場に入れます。

   ```bash
   .venv-finetune/bin/python tools/finetune/finetune.py --task translation --data ~/Desktop/kikimimi-translation.jsonl --model qwen3.5-4b --eval-set <問題.json> --install
   ```

## モデルの選び方

| モデル | 向いている用途 | サイズ |
|---|---|---|
| Large v3 Turbo (軽量版) | 日本語の会議・インタビュー。迷ったらこれ | 約 574 MB |
| Large v3 Turbo | 軽量版より少しだけ高精度 | 約 1.6 GB |
| Large v3 (軽量版) | 最高精度クラス。Turbo の数倍遅い | 約 1.1 GB |
| Medium / Small / Base / Tiny | 速さ優先・動作確認 | 60〜540 MB |

モデルは `~/Library/Application Support/Kikimimi/Models` に保存されます。設定 (⌘,) から取得・削除・フォルダを開けます。

## 設定 (⌘,)

- **画面の言語** (「一般」のタブ): 画面の文の言語を 13 言語から選びます (上の「初回の使い方」)。話されている言語 (文字起こしの言語) とは別の設定です。
- **精度を優先する**: ビームサーチで認識します。オフにすると速くなります。
- **無音を飛ばす (VAD)**: 無音部分を飛ばして処理を速くし、無音での誤認識を減らします (VAD モデル約 0.9 MB を自動取得)。
- **音が続いているのに文字が少ない時は、無音を飛ばさずにやり直す** (既定でオン。「無音を飛ばす」がオンの時だけ): 無音を飛ばす機能は話し声のための物で、伴奏つきの歌を声と見なさず、歌詞がほとんど出ない事があります。文字起こしの後、「結果の区間に入らなかった所の半分以上で、大きな音が鳴っている」と分かった時は、自動で、無音を飛ばさずにもう一度文字起こしします (時間は 2 回ぶんかかります)。やり直した結果を採るのは、文字が 1.5 倍以上、かつ 20 字以上増えた時だけです (静かな録音で、誤ってやり直した結果を採らないため)。そうした結果には、結果の画面に知らせと「無音を飛ばしてやり直す」のボタンが出ます。20 秒より短い音では行いません。
- **日本語と英語が混ざっている録音は、自動で「日本語＋英語」で文字にする** (既定でオン): 言語が「日本語」「英語」「自動判定」のとき、文字にする前に、録音全体から均等に選んだ区切り (発話 3 秒以上、最大 24 個) の言語を確かめます。もう一方の言語がある区切り (多い側でない言語の確率が 0.25 以上。日本語と英語が入っていて判定が確かでない区切りも数えます) が 2 個以上、かつ判定できた区切りの 10% 以上あれば、「日本語＋英語」で文字にします (候補は設定の言語が先。結果は「日本語＋英語」を選んだときと同じ)。1 つの言語だけの録音は、確かめる数秒〜数十秒のほかは今までと同じ結果です。VAD が使えないときと、確かめられる区切りが 4 つ未満の短い録音では確かめません。
- **定番の誤認識と、同じ文の繰り返しを取り除く**: 無音や BGM のところで Whisper が出しがちな「ご視聴ありがとうございました」などを、発話が無さそうなときだけ取り除きます。間を空けずに同じ文が 4 回以上 (2〜3 文の組なら 3 周以上) 続いたときは最初の 1 回だけ残し、1 文の中で同じ語句が 6 回以上続くときも 1 回にまとめます。数分おきに同じことを言う場面や、「No, no, no, no, no.」のような強調、金額・番号は残します。
- **語彙のヒント**: 固有名詞や専門用語 (例: Roblox Studio, ロブロックス) を書いておくと、その表記で出やすくなります。監査と翻訳でも使います。
- **監査・翻訳 (ローカル LLM)**: 「監査・翻訳」タブで、文字起こしのあとに自動で監査するか、日本語以外の区間を自動で訳すか、どの LLM を使うかを選べます。LLM の取得・削除・取り込みもここで行います。
- **訳す先の言語** (「監査・翻訳」のタブ): 翻訳で訳す先を、13 言語から選びます。選んでいない間は、画面の言語と同じです。もう訳してある結果は、その結果の言語のまま続きます。
- **学習した直し / 覚えた訳 / 追加学習 (LoRA)**: 同じタブで、覚えた直しの一覧・削除・追加、覚えた訳 (自分で直した訳) を次の翻訳に使うかと、その一覧・削除、訳語の一覧 (足す・消す)、印を出さなくなった検査の一覧と [元に戻す]、学習用のデータの書き出し、追加学習の差分 (監査の差分・翻訳の差分) を入れる・外す・使う、を行います。「覚えた訳」の節で消すのは覚えた訳だけで、結果に残っている訳はそのままです。
- **チャットから変える**: 上のうち 20 項目は、LLM とのチャットで頼んで、札の「変える」を押しても変えられます (上の「LLM とのチャット」)。リサーチの入・切は、設定には無く、チャットの窓の帯でだけ変えます。

## うまくいかないとき

- **歌や音楽で、歌詞がほとんど出ない**: 無音を飛ばす機能 (VAD) が、歌を声と見なしていません。ふつうは自動でやり直します (上の「設定」)。自動でやり直されなかった時は、結果の画面の「やり直す」›「無音を飛ばさずにやり直す (歌・音楽向け)」を選んでください。歌声と伴奏を分ける機能はありません (下の「既知の制限」)。
- **モデルのダウンロードが失敗する**: Hugging Face (huggingface.co) に接続できる必要があります。会社のネットワーク等で繋がらない場合は、別の環境で次のファイルを入手し、設定の「手元のファイルを追加…」で取り込めます。
  - 音声認識モデル: `ggml-large-v3-turbo-q5_0.bin` (huggingface.co/ggerganov/whisper.cpp)
  - 無音検出 (VAD) モデル: `ggml-silero-v6.2.0.bin` (huggingface.co/ggml-org/whisper-vad)。無くても動きます。取れなかったときは 10 分おきに取り直します。
- **LLM のダウンロードが失敗する**: 音声認識モデルと同じく Hugging Face に接続できる必要があります。繋がらない場合は、別の環境で Qwen3.5 の GGUF (例: huggingface.co/unsloth/Qwen3.5-4B-GGUF の `Qwen3.5-4B-Q4_K_M.gguf`) を入手し、設定の「手元の GGUF を追加…」で取り込めます。
- **翻訳が遅い / Mac が重くなる**: 設定で LLM を「Qwen3.5 2B (軽量)」に替えてください。翻訳は「中止」でいつでも止められ、訳せた所までは残ります。「残りを翻訳」で続きから訳せます。
- **監査の直しが気に入らない**: 「監査: …」の一覧で、その直しのチェックを外すと元に戻ります。「すべて元に戻す」もあります。
- **起動しない / ウインドウが出ない**: 次を実行すると、環境・組み立てたアプリ・起動の確認・クラッシュの記録を `build/doctor.txt` にまとめます (途中でウインドウが出て、数秒で自動的に閉じます)。その内容をそのまま報告してください。

  ```bash
  make doctor
  ```

  ウインドウを閉じたまま動いているとき (文字起こしや翻訳の途中) は、Dock のアイコンを押すか、メニューの「ファイル > メインウインドウを表示」(⌘0) で開き直せます。作業中でなければ、ウインドウを閉じるとアプリも終了します。終わった結果とメモは保存してあり、次に起動したときも一覧に出ます。作業の途中で終了 (⌘Q) しようとすると、途中の作業が止まることを確かめます (文字起こしの途中の結果は残りません)。
- **`make run` で whisper.framework / llama.framework が見つからないと言われる**: 次を実行してから、もう一度 `make run` してください。

  ```bash
  swift package reset
  ```

- **マイク許可のダイアログが出ない / 拒否してしまった**: システム設定 › プライバシーとセキュリティ › マイク で「ききみみ」をオンにします。作り直して署名が変わった場合は、次を実行してから起動し直してください。

  ```bash
  tccutil reset Microphone local.kikimimi.app
  ```

- **録音中に AirPods をつないだ / 入力を切り替えた**: 新しい入力で録音を続けます。続けられなかったときは、そこまでの録音を文字起こしします。
- **同じ文が延々と繰り返される (1.0.0 の不具合)**: 1.0.0 では、30 秒ごとの区間で認識した文章を次の区間の手がかりとして渡していたため、音楽や雑音で一度誤認識すると、その文が後ろの区間すべてに連鎖しました。1.0.1 で直しています。1.0.0 で文字起こししたファイルは、失われた部分を取り戻すために、もう一度文字起こししてください。
- **webm / mkv / ogg が読めない**: AVFoundation が対応していない形式です。QuickTime Player か ffmpeg で m4a / mp4 に変換してから使ってください。
- **起動時に「開発元を確認できない」と出る**: 自分でビルドしたアプリは通常出ませんが、出た場合は Finder でアプリを右クリック › 開く を選んでください。

## テスト

書き出し・モデル一覧・WAV・誤認識フィルタ・監査・翻訳など UI に依存しない部分は `KikimimiCore` に分けてあり、テストできます。

```bash
swift test
```

組み立てたアプリで文字起こしを動かす診断もあります (画面は出ません)。区切りごとの言語の判定・文字にした範囲・点検で引っかかったところと直し・区間ごとの言語・かかった時間・使ったメモリを表示します。モデルと VAD は、指定が無ければアプリで取得したものを使います。`--from` / `--to` (秒) で一部だけ、`--languages ja` で「日本語」の設定、`--auto-mixed` で (`--languages ja` などと一緒に) 日本語と英語が混ざっているかを先に確かめる設定 (確かめた区切りと結果を表示します)、`--no-vad` で無音を飛ばさない (VAD を使わない。取得済みの VAD が在っても)、`--auto-vad-off` でアプリの「音が続いているのに文字が少ない時は、無音を飛ばさずにやり直す」と同じ動き (やり直した時は、その 1 行と、採った結果がどちらかを表示します)、`--report` で結果を JSON に書き出します (`--auto-vad-off` の時は、やり直したか・採ったほうも入ります)。

```bash
build/Kikimimi.app/Contents/MacOS/Kikimimi --selftest-whisper ~/Downloads/lecture.mp3 --languages ja,en --from 120 --to 240 --report ~/Desktop/kikimimi-report.json
```

組み立てたアプリで LLM をひと通り動かす診断もあります (画面は出ません)。取得した LLM で例文を訳し、監査し、かかった時間を表示します。`--strict` を付けると、訳がすべて日本語か・聞き間違い (Roblocks → Roblox) を直せたかまで確かめます。`--cpu` で GPU を使わずに動かします。`--translate-to <言語のコード>` (en・zh・ko など 13 言語) を付けると、例文をその言語へ訳し (en なら日本語の例文、ほかは英語の例文を訳す)、`--strict` では 3 行以上がその言語らしい訳か (韓国語・ロシア語・タイ語・中国語・日本語はその言語の文字を含むか、ほかは原文と違うか) を確かめます。

```bash
build/Kikimimi.app/Contents/MacOS/Kikimimi --selftest-llm ~/Library/Application\ Support/Kikimimi/Models/LLM/qwen3.5-4b.gguf --strict
```

チャットの答えを本物の LLM で測る診断もあります (画面は出ません。`--selftest-chat`)。答えが少しずつ出るか (`CHAT STREAM OK`) と、日本語 8・英語 8 の問題で、頼んだ設定の印を出し、頼んでいない印を出さないか (`CHAT EVAL: <合った数>/16`) を出します。先に `make app` で作っておきます。

```bash
make check-chat LLM=~/Library/Application\ Support/Kikimimi/Models/LLM/qwen3.5-4b.gguf
```

文書とアプリが使うリンクが切れていないかを見る道具もあります (ネットにつなぎます)。アプリが実行時に使う URL は、モデルの一覧 `Sources/KikimimiCore/Catalog/models.json` から作ります (`--list-runtime` で一覧だけ出せます)。アプリが作る URL と同じである事を `swift test` の `LinkListTests` が見ます。切れが在ると終了コード 1 です。

```bash
make check-links
```

## 設計メモ

- **whisper.cpp を選んだ理由**: macOS 14 で動き、Metal で速く、ビルド済みの公式 XCFramework があるので C/C++ のビルドが不要です。日本語の精度は OpenAI Whisper と同じモデルなので同等です。
- **macOS 26 の SpeechAnalyzer** は将来の選択肢です。macOS 26 に上げた場合は、エンジンを差し替えられる構成にしてあります。
- **長い音声と繰り返しの暴走**: Whisper は 30 秒ずつ処理します。whisper.cpp の既定では、直前の区間で認識した文章を次の区間の手がかりとして渡します。`no_context` はこれを止めません (前回の呼び出しの文脈を捨てるだけです)。そこで `n_max_text_ctx = 0` にして区間どうしの引き継ぎを止め、OpenAI 版の `condition_on_previous_text=False` と同じ動きにしています。語彙のヒントは `carry_initial_prompt` で毎区間に付け、`n_max_text_ctx` を「ヒントのトークン数 + 1」に絞って、前の区間の文章が入らないようにしています。区間内で繰り返しになったときの言い直しは、ビームサーチでも 5 候補から選びます (`greedy.best_of = 5`、whisper-cli と同じ。既定のままだと 1 候補だけの抽選になります)。繰り返しとみなす基準 (`entropy_thold`) は既定の 2.4 のままです。上げると普通の発話でも言い直しが増えて遅くなり、音楽部分のでたらめな文もかえって片付けにくくなることを、再現実験で確かめました。それでも残った分は後始末で片付けます。
- **監査と翻訳にローカル LLM を選んだ理由**: 無料で、音声の内容を外へ出さずに済み、オフラインでも動くからです。llama.cpp は Metal で速く、ビルド済みの公式 XCFramework があります。小さなモデルでも形が崩れないよう、出力は GBNF 文法で「番号・行数」まで縛り、1 行が長すぎたら打ち切ります (同じ語を延々と出す暴走の歯止め)。答えは貪欲法で決めるので、同じ入力には同じ答えを返します。
- **whisper.cpp と llama.cpp の同居**: 2 つのフレームワークは、版の違う ggml.h をそれぞれ持っています。Swift で両方の C モジュールを 1 つのコンパイルに入れると型の定義がぶつかるので、C モジュールは各ラッパーの中だけで使い (`internal import`)、ラッパーと KikimimiCore を library evolution でビルドして、アプリ本体のコンパイルに持ち込まないようにしています。実行時の記号の重なりも確かめてあります (互いに呼び合うことはありません)。
- **日本語＋英語**: whisper は 30 秒ずつ、1 つの言語の指定 (`<|ja|>` など) で文字にします。VAD は間を 0.1 秒に詰めるので、英語と日本語が入れ替わる録音では、1 つの 30 秒に両方の言語が入ります。日本語の指定で英語を聞くと「彼は、彼は、…」のような繰り返しになり、それを後始末で縮めたものが、英語の中に 1 行だけ残る崩れた日本語の正体でした (英日を交互に並べた録音で再現。誤りは 25%)。自動判定も、最初の 30 秒で 1 回決めるだけなので役に立ちません。「日本語＋英語」では、VAD で見つけた発話を 28 秒以内の区切りにまとめ、区切りごとに whisper の言語判定を日本語と英語の 2 つだけで比べます (候補を絞らないと、短い音声で中国語や韓国語を作り出します)。判定が揺れる区切りは、中の長い間で分けて判定し直し、間を空けずに入れ替わるところは 4 秒・2 秒の窓の二分探索で探します (話し声が 1 秒に満たない窓は、無音に近い判定が当てにならないので、1 秒話すところまで広げてから判定します)。確からしさの高い区切りでも、別の言語の確率がそのファイルのふつう (英語の区切りの中央値の 5 倍) より高ければ、区切りを半分ずつにして、中ほどに挟まった短い別の言語 (島) を探します。英語で文字にすると、日本語の一言は訳されずに消え、点検にも何も残らないためです。雑音で全体に広がった揺れは、両端の窓や最初に分けた半分どうしを比べて見分け、探しません。同じ言語の区切りをつないで (最長 10 分)、今の「日本語」と同じ設定でその言語で文字にし、繰り返し・自信の低さ・話した長さに合わない文字の量・抜けを安く点検します。引っかかったところは判定し直し (確からしさが低ければ、先に切り替わりと島を探します)、別の言語の部分を、重なる元の区間の全体まで広げてその言語で文字にし直し、良くなったときだけ入れ替えます (同じ言語なら元のまま。文字にし直して何も出なければ、元の文を残します。点検は文を消しません)。数値は、英日の朗読 (FLEURS) と日本語の講演で測って決めました。
  「日本語」「英語」「自動判定」でも、文字にする前に同じ VAD と区切りを作り、録音全体から均等に選んだ区切り (発話 3 秒以上、最大 24 個) を日本語と英語の 2 つだけで判定します。判定の確率の合計が多い側を多い側の言語とし、もう一方の言語の確率が 0.25 以上の区切り (もう一方の言語と判定された区切りと、判定が確かでない区切り) が 2 個以上、かつ判定できた区切りの 10% 以上なら、「日本語＋英語」で文字にします。通訳が短く交代する講演では、ほとんどの区切りに両方の言語が入って判定が確かでなくなるので、確かでない区切りも混ざっている証として数えます (1 つの言語だけの録音では、区切りの判定は 0.977 以上でした) (このとき、確かめたときの VAD と判定を使い回します)。混ざっていなければ、今までと同じ 1 つの言語の文字起こしです。2 時間の講演 (英語の講師と日本語の通訳) を「日本語」のまま文字にすると英語の部分が崩れたため、選び直さなくても済むようにしました。
- **ファインチューニングよりハーネスが先**: 小さな LLM の弱点 (何でも直したがる・説明を書いてくる・同じ誤りを何度もする) の多くは、重みを変えなくても、まわりの仕組みで止められます。そこで、(1) 利用者の決定を覚えて機械的に当てる台帳、(2) 答えを反映する前の関門、(3) 変更の前後を同じ場面で比べる評価ハーネス、を先に作りました。台帳は 1 件目から確実に効き、学習の時間もメモリも要りません。追加学習 (LoRA) は、直しが数十件たまってから、評価ハーネスで「悪くなっていない」と確かめられたときだけ使う位置づけです。
- **署名**: ad-hoc 署名です。人に配る場合は Developer ID での署名と公証に差し替えてください。

## 既知の制限

- 話者分離はありません。「日本語＋英語」は声ではなく、話している言語で区切ります。
- 「日本語＋英語」でも、間を空けずに入れ替わるところでは前後 1.5 秒ほどが抜けることがあります。1.5 秒より短い差し込み (相づちなど) や、雑音の多い録音の中の差し込みは、見つからずに前後の言語で文字になったり抜けたりすることがあります。
- 自動判定は最初の 30 秒で言語を 1 回決めるだけです。日本語と英語なら、混ざっているかを先に確かめて「日本語＋英語」に切り替えます (設定でオンのとき) が、英語の中の短い日本語の一言 (3 秒未満) だけの録音は「混ざっていない」と判定されやすいので、一言も拾いたいときは「日本語＋英語」を選んでください。
- 翻訳の質は、Mac の中で動く小さな LLM (Qwen3.5) の力によります。日本語のほかの 12 言語への翻訳は、2026-11-15 に、Qwen3.5 4B で、言語ごとに例文 4 行を訳して、その言語の文字で訳が出る事だけを見ました (訳の正しさを、その言語を話す人が見たわけではありません。日本語 → 英語では「再生のボタン」が "restart button" になる誤りが在りました)。訳の検査 (中国語に流れた訳を弾く、など) は日本語へ訳す時がいちばん厚く、ほかの言語では、空の訳・長すぎる訳・その言語の文字が 1 つも無い訳 (韓国語・ロシア語・タイ語) を弾くだけです。2026-11-16 からは、訳す先によらず、関門が疑わしい訳に「要確認」の印を付けます (上の「訳を直す・覚えた訳・要確認」)。印を付けるだけで、訳は入れ替えません。訳の後ろが抜ける (LLM が、長い原文の初めの 1〜2 文だけを訳して終える) 事は、13 言語すべてで起きていました。この時だけは、文に分けて訳し直し、直った時に入れ替えます (上の「訳を直す・覚えた訳・要確認」)。
- 言語が分からない区間 (文字起こしの言語が「自動判定」で決まらなかった時など) は、訳す先が日本語でない時、全部を訳す対象にします (もうその言語の行は、そのまま写すよう LLM に指示しています)。評価ハーネス (`--eval-llm`) の翻訳の採点は、訳す先ごとに行います (日本語のほかの言語の「その言語か」は macOS の言語の判定によるので、8 字に満たない訳は判定しません)。
- 「〇〇で訳し直す」の前に自動で残る版には、履歴の画面で「自動 (訳し直す前)」の印が付きます (版の名前は「訳す先の言語を変える前」)。2026-11-26 より前のアプリが残した版は、「自動 (戻す前)」の印のままです。2026-11-26 より前のアプリで、新しい印の版が在る結果を開くと、その版は印が付かず、自分で残した版として扱われます。書き出しの CSV の訳の列の名前は、訳す先が日本語なら `japanese`、ほかの言語なら `translation` です。
- 関門の数の検査は、単位や桁を言い換えた正しい訳にも印を付けます (人の訳で約 1%)。そのため、印を付けるだけで、訳し直しや入れ替えには使いません。
- 訳を直すシートを開いている間に翻訳が進み、その行が別の文のまとまりに入ると、保存した訳は、今のまとまりに置かれます。
- 直した文で「この文を訳し直す」を押して失敗すると、直した訳は残りますが、印「直した」は消えます。
- 訳せなかった理由は、文のまとまりの先頭の行にだけ出ます。
- 「要確認 N」を押しても、検索で絞って一覧に無い行へは移れません。
- 数千行の結果の文字起こしを、末尾を追いかけながら見ている時に、数百行がいっぺんに届くと、画面が 0.4〜2.2 秒ほど止まる事があります。GitHub の Mac (macOS 15) で、確認用のデータ (8000 行に 300 行をいっぺんに足す) で見た物です。起きるかどうかは、その時の行の数で決まっていました (同じ行の数なら、毎回起きました)。macOS 14 の Mac では起きていません。2026-11-28 から、macOS 15 以降では、11 行以上がいっぺんに届いた時は、末尾へ 10 行ずつ動かして追いつきます (GitHub の Mac で、1 回の止まりは 0.02〜0.25 秒になり、300 行に追いつくのに 0.8〜1.5 秒かかります)。600 行より多くたまった時・窓を隠していて戻った時・「末尾へ」のボタンで離れた所から跳ぶ時は、今までどおり 1 回で跳ぶので、止まる事が在りえます。本物の音声認識で測ると (M1 の Mac、large-v3-turbo、20〜32 分の音声を 3 通り)、1 秒の中に届いた行は多くて 8 行で、数百行がいっぺんに届く事はありませんでした。ふつうの文字起こしでは、この形になりにくいはずです。macOS 15 以降の実機では確かめていません。原因の調べは `docs/HANDOFF.md` (2026-11-27)。
- 訳語の当て方 (頭の 75%) は、頭の同じ別の語に当たる事が在ります。ラテン文字の語の切れ目は「前後が文字でない」で見るので、"car" は "car2" にも当たります。
- 「この訳でよい」を押した後で、その訳を直しても、「検査が当たった」には数えません。
- 文に分けて訳し直すと、そのまとまりは、LLM の呼び出しが 1 回以上増えます。
- 翻訳には、翻訳の差分だけを使います。翻訳の差分が無い時は、監査の差分を入れていても、翻訳は差分なしです。見立ての記憶で学習させた翻訳の差分は、評価で「採らない」でした (学習させた日本語・韓国語の chrF が下がりました。上の「翻訳の追加学習」)。本物の直しで学習させた差分の効き目は、まだ分かりません。
- 16 GB の Mac で 4B を追加学習させると、メモリを使い切ります (30 回の時の最大は 16.0 GB・スワップ 0。400 回の時は peak memory footprint 28.0 GB で、スワップを使いました)。学習の間、ほかの重い作業 (文字起こし・翻訳など) は遅くなります。
- 訳が数を言葉で書いた時 (10 → 十、30 → 三十、30 → Tiga puluh、35 → thirty-five) は、数の検査は印「要確認」を付けません (2026-11-19 から。訳す先の言語でその数を言葉にした形が訳に在れば、数が残っていると見ます)。言葉の形でも印が付く書き方が残っています: 韓国語の固有の数え方 (서른・열)、女性形や格で形が変わる数 (veintiuna・двадцать одна)、「两」「廿」「一百」のような別の書き方、「30万」のように桁を言い換えた形。逆に、日本語・韓国語・タイ語・中国語では、訳の中の別の語がたまたまその数の言葉を含むと (100 と「百貨店」)、数が消えていても印が付きません。
- 結果の画面の操作の列 (検索・チェック・ボタン) は、窓の幅に合わせて 1 行・2 行・印だけのボタンに並べ替わります。英語の画面で、窓からはみ出して右の端と左の一覧が切れていた事は、2026-11-19 に直しました (英語・ドイツ語・タイ語・日本語の画面で、横およそ 1200 の窓で見ました)。2026-11-20 に、ほかの 9 言語の画面でも、左の一覧と右端の「書き出し」が窓の中に見える事を、確認用の起動の絵で見ました。2026-11-27 に、窓のいちばん狭い横幅 (880 pt) の絵を、確認用の起動に足しました (日本語・英語・ドイツ語・ロシア語の画面で見ました。窓の外へ出る物・重なる物は在りませんでした)。横 880 pt でメモの欄を開くと、一覧は 360 pt ほどになり、対訳の行は縦に長くなります。英語やドイツ語の画面で、行の札 (「Translate line」など) の語が途中で折れていた事は、2026-11-27 に直しました (訳の列が狭い時は、札とボタンを訳の文の下に並べます。日本語・英語・ドイツ語の画面で見ました)。ドイツ語の画面では、この幅で、見出しの「Übersetzung」の語が途中で折れます (直していません)。880〜1200 pt の間の幅と、ほかの 9 言語の横 880 pt は見ていません。
- 似た文を手本にする仕組みは、評価のための実験の口です。アプリの翻訳では使いません (2026-11-16 の測りで、効き目が「変わらない」だったため。似た文が少ない記憶での測りなので、似た文が多い時の効き目は分かっていません)。
- 「日本語＋英語」は、「無音を飛ばす (VAD)」をオンにして使ってください (既定)。オフだと、無音のところの言語の判定が当てにならず、無い切り替わりを作って数秒を別の言語で文字にすることがあります。
- 監査の「学習した直し」は、語の置き換えです。同じ語が、ある行では誤りで別の行では正しい、という直し (同音の語の取り違えなど) は、1 回の反映では提案どまりにしてありますが、2 回反映すると自動になります。合わなくなったら、設定の「学習した直し」から削除してください。
- 録音中のプレビューは直近 12 秒ぶんだけです (止めると全体を認識し直します)。
- 歌の文字起こしは、話し声ほど正確ではありません。歌声と伴奏を分ける機能 (音源分離) はありません。2026-11-15 に、日本語の歌 1 曲 (154 秒) で試した範囲では、Demucs で分けた歌声を文字起こししても、元の音を無音を飛ばさずに文字起こしした時より良くはなりませんでした (20 区間と 23 区間。別の誤りが出る)。伴奏だけの所で、無い文が出る事があります。
- 「音が続いているのに文字が少ない時」の判定は、音の大きさで決める目安です。騒がしい場所で、話が少ししか無い録音でも、自動のやり直しが起きる事があります (時間が 2 回ぶんかかり、雑音の所に無い文が出る事があります)。その時は「無音を飛ばしてやり直す」を選ぶか、設定でこの機能を外してください。
- 画面の言語を変えても、もう保存してある文は、作った時の言語のまま残ります (監査の理由、版の名前「戻す前の状態」、録音の名前「録音 11/15 16:34」など)。書き出したファイルの見出しは、書き出した時の画面の言語になります。
- 日本語と英語のほかの 11 言語の画面の文は、AI の訳です (その言語を話す人の確認は無い)。語が長い言語では、ボタンや見出しが切れて見える所が在るかもしれません。訳は `Sources/KikimimiCore/L10n/<コード>/<コード>.swift` (チャットの文は `<コード>+Chat.swift`) の値を書き換えると直せます。
- 「ゴミ箱に入れる」は、macOS のゴミ箱に入れられなかった時 (ゴミ箱の無い場所など) は、その場で消します。アプリの中に「戻す」のボタンはありません (ゴミ箱から取り出したフォルダを、ライブラリのフォルダに戻して起動し直した時に、一覧へ戻るかは、まだ確かめていません)。
- 消せるのは、一度に 1 つの結果です (いくつかまとめて選んで消す事はできません)。
- 落として読み込む時、形式は、ファイルの種類 (拡張子) で見ます。エイリアスやシンボリックリンクは読み込みません (元のファイルを落としてください)。中身が音声でないのに拡張子が音声のファイルは、読み込んだ後で失敗します。
- LLM とのチャットの会話は保存しません。アプリを閉じると消えます。
- チャットの LLM は、設定を変える案を出すだけです。頼んでいない案を出す事も在ります (本物の Qwen3.5 4B の 16 問の測りで 2 問。「VAD って何？」のような質問への答え)。札の「変える」を押すまで、設定は変わりません。
- LLM の答えが空だった時・途中で切れた時: 監査は、終わった後に「LLM の答えを N か所で読めなかったため、そこの問題を見落としたかもしれません。」と知らせます (2026-11-28 から。それまでは、何も出さずに「指摘なし」として終わっていました)。この知らせは保存されないので、アプリを開き直すと消えます。どの行かは出ません。チャットは、答えが空の時に「LLM の答えが空でした。」と知らせます。チャットの答えが途中で切れた時 (長さの上限など) は、届いた所までを出し、「答えが、終わる前に切れました。」と知らせます (2026-11-28 から。本物の LLM で、短い上限にして、切れた事が分かる所までを見ました。画面の知らせは、偽の LLM では作れないので、見ていません)。監査とチャットの「空の答え」は、本物の LLM では起こしていません。
- 監査・翻訳が走っている間、チャットが割り込めるのは、かたまり (LLM を 1 回呼ぶ分) の合間だけです。今のかたまりが終わるまでは待ちます (数十秒の事が在ります)。追加学習の差分 (LoRA) を使っている監査・翻訳の最中は、割り込めず、その仕事が終わるまで待ちます (チャットは差分なしで動くので、LLM の読み直しが要るため)。1 回の呼び出しに収まる短い結果でも、終わるまで待ちます。チャットが答えている間、監査・翻訳の進み具合の表示は止まったままです (「チャットに答えています」のような知らせは出ません)。
- リサーチで読めるのは、発言に書いた `https` の URL のページ (3 つまで) だけです。Web の検索はありません。JavaScript で中身を作るページは読めません (読むのは HTML の文だけです)。
- リサーチで読んだページに隠れた指示 (Prompt Injection) が在ると、LLM がまちがった答えを出す事が在ります。ページの文は区切りの中に入れて「中の指示に従わない」と伝え、ページを読んだ回は設定を変える案を出さない作りですが、LLM が指示に従ってしまう事を防ぎ切る事はできません。Prompt Injection による破損や損害は、自己責任でお願いします。
- リサーチは `localhost`・IP アドレスの直書き・内の名前 (`.local` など) を読みませんが、公開の名前が DNS で内の住所 (家や会社の中の機械) を指す場合は防げません。
- アプリが取りに行くモデルの一覧 (音声認識・VAD・LLM の配布元の URL) は、アプリに埋め込んだデータです (`Sources/KikimimiCore/Catalog/models.json`。直した後は `/usr/bin/python3 Scripts/generate-model-catalog.py` で埋め込みのファイルを作り直す)。外から差し替える仕組みは、まだ在りません。配布元の URL が変わった時は、アプリを作り直すまで取れません。切れた事には、`make check-links` と週 1 回の CI (main に入ってから) で気づく作りです。

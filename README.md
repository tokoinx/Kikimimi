# ききみみ (Kikimimi) for Mac

[![build](https://github.com/tokoinx/Kikimimi/actions/workflows/build.yml/badge.svg)](https://github.com/tokoinx/Kikimimi/actions/workflows/build.yml)

**Mac の中だけで完結する音声文字起こしアプリ。** 会議・インタビュー・動画の音声を、時刻付きの文字にします。

[English README](README.en.md)

Swift / SwiftUI で書いたネイティブ Mac アプリです。音声認識には **whisper.cpp** (OpenAI Whisper の C/C++ 実装)、監査と翻訳には **llama.cpp** と無料の小さな LLM (**Qwen3.5**) を使い、どちらも Apple Silicon の GPU (Metal) で動きます。
音声も文字起こしの内容も Mac の外に出ません。インターネットを使うのは、最初にモデルを取得するときだけです。

- 音声・動画ファイル (mp3 / m4a / wav / aiff / caf / mp4 / mov …) をドロップ → 時刻付きで文字起こし
- Finder の「このアプリケーションで開く」や Dock アイコンへのドロップでも追加できます
- 認識できた文から順に画面へ表示。途中で中止もできます
- マイク録音 (録音中は数秒ごとに直近の内容をプレビュー、止めると全体をていねいに認識)
- 行をクリックすると、その行だけを再生 (もう一度クリックで停止。右クリックの「ここから続けて再生」で、その位置から続けて再生)、検索ハイライト
- **監査役**: 文字起こしのあと、同じ文の繰り返しと聞き取りミスを見直します。自信のある直しだけを反映し、それ以外は「提案」として残します。どの直しも一覧で確かめて元に戻せます
- **英語 → 日本語の翻訳**: 左に原文、右に日本語訳を並べて表示します (中国語・韓国語なども日本語に訳せます)。まとめて訳すほか、行の「訳」で読みたい文だけを 1 文ずつ訳せます
- 書き出し: txt / srt / vtt / Markdown / csv / json (原文・日本語訳・対訳)
- 言語: 日本語・英語・中国語・韓国語など (自動判定も可)
- **日本語＋英語**: 英語の講師と日本語の通訳のように、日本語と英語が入れ替わる録音向けの設定です。区切りごとに話している言語を判定し、その言語で文字にします。行には「英」「日」の印が付き、英語の行だけを訳します (時間は「日本語」の 2〜4 倍ほど。言語の入れ替わりや短い差し込みが多いほど長くなります)。言語を「日本語」「英語」「自動判定」にしていても、日本語と英語が混ざった録音だとわかれば、自動でこの設定に切り替えて文字にします (結果の画面に知らせが出て、元の言語だけでやり直すこともできます。設定で切れます)

## 必要なもの

- macOS 14 (Sonoma) 以降。Apple Silicon 推奨 (Intel Mac でも CPU で動きますが遅くなります)
- Xcode 16 以降、または Command Line Tools (`xcode-select --install`)
- 空きディスク 1 GB 程度 (おすすめの音声認識モデルが約 574 MB)。監査・翻訳も使うなら、さらに約 3 GB (おすすめの LLM が約 2.7 GB)
- メモリ 8 GB 以上 (LLM の 9B モデルは 16 GB 以上)

## ビルドと起動

```bash
git clone https://github.com/tokoinx/Kikimimi.git
cd Kikimimi
make run
```

`make run` は次をまとめて行います。

1. `swift build -c release` (初回は whisper.cpp と llama.cpp のビルド済みフレームワーク 約 54 MB + 約 65 MB を GitHub から取得)
2. `build/Kikimimi.app` の組み立てと whisper.framework / llama.framework の同梱
3. ad-hoc 署名
4. 起動 (ききみみが起動中なら、いったん終了させてから新しいものを開き、数秒後に動いているかを確かめます。動いていなければ、原因を調べて `build/doctor.txt` にまとめます)

起動は `make run` で行ってください。`open build/Kikimimi.app` だけだと、前のものが動いているときは新しい版が起動しません。

`/Applications` に入れるなら:

```bash
make install
```

### 初回の使い方

1. 起動すると「モデルをダウンロード」ボタンが出ます。おすすめの **Large v3 Turbo (軽量版)** は約 574 MB で、一度取れば以後はオフラインで動きます。
2. 音声ファイルをウィンドウに落とすか ⌘O で開きます。
3. 認識できた文から順に右側へ出ます。終わったら「書き出す」で保存します。

録音 (⌘R) を使うと、初回だけマイク許可のダイアログが出ます。

監査と翻訳を使うときは、LLM を一度だけ取得します。起動したときの画面や結果の画面に出る「ダウンロード」か、設定 (⌘,) の「監査・翻訳」タブから取得できます。取得後は、文字起こしが終わるたびに自動で監査し、英語などの区間を日本語に訳します。

## 監査と翻訳 (ローカル LLM)

文字起こしの結果を、Mac の中で動く小さな LLM がもう一度読み直します。

- **監査役 (聞き取りミス・繰り返しの見直し)**
  - 規則: すぐ前と同じ文・ほぼ同じ文・一部の繰り返しを見つけます。自動で消すのは、句読点まで同じ長めの文が、すき間なく 2 度続いたとき (同じ音声を 2 度読んだもの) だけです。間をあけたくり返し (何人かが順に言うあいさつ・語学の練習)・言い直し (「月曜に」→「火曜に」)・聞き返し (「〜です。」「〜ですか？」) は消さずに提案にとどめ、数字が違う文は別の文として扱います。
  - LLM: 文脈から見て明らかな聞き間違い (同音の別の語、崩れた固有名詞) と、実際には話していない文 (無音や音楽のところの「Thank you for watching.」など) を見つけます。
  - 直し方: LLM には行ぜんたいを書き直させず、「聞き間違えた語 => 正しい語」だけを答えさせて、元の行のその語だけを置き換えます (行に無い語の指摘は使いません)。答えの形は文法で「問題のある行だけを番号順に 1 回ずつ、最後に END」に縛ってあるので、同じ指摘をくり返す暴走が起きません。
  - **評価役**: LLM が出した直しは、「直す前」と「直した後」のどちらが実際に話された文かを、並びを入れ替えて 2 回たずね直します。2 回とも直した方を選んだときだけ自動で反映し、判断が割れたら提案どまり、2 回とも直す前を選んだら捨てます (小さなモデルの「1 番目を選びがち」などの癖を打ち消すためです)。
  - 安全の基準: さらに、直す量が少ない・言語が変わらない (翻訳になっていない)・語を足す/削るだけの手直し (助詞や語尾) ではない、を満たす直しだけを自動で反映します。数字が変わる直し (「3時」→「5時」)・否定が変わる直し (can't → can)・漢字が新しく入る直しは、LLM が音声を聞いていない以上は推測なので、必ず提案にとどめます。英語の語は語の切れ目で合わせます (can を直すつもりで scan を変えない)。削除は、近くに同じ文が「残る」ときだけ自動にします。1 回の見直しで半分近くの行を直したがる答えは、書き換えとみなしてすべて提案どまりにします。「ご視聴ありがとうございました」のような定番の文は、実際にそう話すこともあるので提案どまりです。
  - 監査をやり直しても、あなたが反映した・取り消した直しはそのまま引き継ぎます。途中で中止したり LLM が使えなかったりしても、規則の見直しと、見終えた所までの結果は反映します。
  - 結果の画面の「監査: 修正 3 · 削除 2 · 提案 1」から一覧を開き、1 か所ずつ反映・取り消しができます。行の横の印 (修正済み / 修正の提案 など) を押しても確かめられます。
- **翻訳役 (日本語へ)**
  - 日本語以外の区間を、文ごとに日本語に訳します。Whisper の区間は文の途中で切れることが多く、区間ごとに訳すと日本語の語順のせいで訳が隣の区間にずれるため (本物の Qwen3.5 4B で確かめました)、続いている区間を文の終わりまでまとめて 1 行として訳し、その訳を右の列で複数の区間にまたがって表示します。数行ずつまとめて訳し、番号と行数は llama.cpp の文法 (GBNF) で縛ります。読めなかった行は 1 行ずつ訳し直します。
  - Qwen は訳文が中国語に流れることがあるので、日本語の手本のやりとりを先に見せ、日本語に出てこない漢字 (簡体字など) は出力の候補から外しています。
  - 画面は左に原文、右に日本語訳。もともと日本語の区間は、右の列に原文を薄く出します。「対訳」のチェックで切り替えられます。
  - 設定の「語彙のヒント」に書いた固有名詞は、監査と翻訳でもその表記を使います。
  - **1 文だけ訳す**: まだ訳のない日本語以外の行には「訳」が出ます。押すとその行を含む 1 文だけを訳します (メモリ 8 GB の Mac で全体を訳すのが重いとき向け。自動の翻訳を設定で切っても使えます)。文のまとめ方とプロンプトは「翻訳」と同じなので、あとで「翻訳」「残りを翻訳」を押しても、訳した文は飛ばします。いくつか押すと順に訳し、待っている行・訳している行は「訳」がくるくるに変わります。「中止」で止められます。訳のある行は、右クリックの「この文を訳し直す」で訳し直せます。
- 手動でも実行できます: 監査 ⇧⌘K、翻訳 ⇧⌘T (結果の画面のボタンでも)。

| LLM | 向いている用途 | サイズ | メモリ |
|---|---|---|---|
| Qwen3.5 4B | 監査と翻訳のバランスが良い。迷ったらこれ | 約 2.7 GB | 8 GB 以上 |
| Qwen3.5 2B (軽量) | 速さ優先。精度は控えめ | 約 1.3 GB | 8 GB 以上 |
| Qwen3.5 9B (高精度) | いちばん賢いが遅い | 約 5.7 GB | 16 GB 以上 |

- どれも Apache-2.0 の無料モデルです。量子化 Q4_K_M の GGUF を Hugging Face から取得し、`~/Library/Application Support/Kikimimi/Models/LLM` に `qwen3.5-4b.gguf` (2B は `qwen3.5-2b.gguf`、9B は `qwen3.5-9b.gguf`) という名前で保存します。取得中は一時ファイルに書き、ダウンロードが終わって中身を確かめてから、このフォルダに移します (それまではフォルダに現れません)。確かめるのは、GGUF であることと、Hugging Face のファイル一覧にある大きさと SHA-256 です (一覧を取れなかったときは、GGUF であることだけ)。設定の「LLM のフォルダを開く」で Finder に表示できます。
- ダウンロードの途中でアプリを終了すると取得は中止され、次は最初からやり直しになります (設定のウインドウを閉じても、取得は続きます)。
- 手持ちの GGUF (llama.cpp で動くもの) も、設定の「手元の GGUF を追加…」で使えます。
- 目安: 1 時間の英語の講演なら、M1 で監査に数分、翻訳に 10〜20 分ほどかかります (4B の場合。訳は終わった所から順に右の列に出ます)。急ぐときは 2B を選んでください。
- メモリ 12 GB 未満の Mac では、音声認識のモデルと LLM を交互に読み込んで、同時にメモリを使わないようにしています。
- 小さな LLM なので、クラウドの大きなモデルほど賢くはありません。監査は「自信のあるものだけ自動、それ以外は提案」にしてあるので、大事な文書では提案を確かめてから使ってください。

## 学習した直し・評価ハーネス・追加学習

小さな LLM は、それだけでは頼りになりません。ききみみは、LLM のまわりに「覚える・確かめる・測る」仕組み (ハーネス) を置いて支えています。追加学習は、その上に重ねる任意の手段です。

### 学習した直し (記憶)

- 監査の一覧で直しを **反映** したり **元に戻し** たりすると、その決定を「聞き間違えた語 → 正しい語」として覚えます。設定の「監査・翻訳」の「学習した直し」で、一覧・削除・自分での追加ができます。
- 反映した直しは、次の監査から LLM に聞く前に当てます (一覧には「学習した直し」と出るので、いつでも元に戻せます)。元に戻した直しは、LLM がまた出してきても使いません。正しい語は、文字起こしと翻訳の語彙のヒントにも足します。
- 1 回反映しただけの直しは、次は **提案** として出します。2 回反映すると、次から **自動** で直します (その行でだけ正しい直し、たとえば「break → brake」「機関 → 期間」を、1 回の反映でどの録音にも当たる規則にしないためです)。数字や否定が変わる直し・かなを漢字にする直しは、何回反映していても提案どまりで、行ごとに確かめます。設定で自分で追加した直しは、いつも自動で当てます (「T-pie → TPIE」のような大文字や記号だけの直しも)。
- この行では元に戻した、という決定は、その文字起こしの監査をやり直しても引き継ぎます。
- 保存先は `~/Library/Application Support/Kikimimi/learned-corrections.json` で、Mac の外には出ません。LLM を取得していなくても働きます。

### 関門 (機械の点検)

LLM の答えは、反映する前に機械で点検します (評価役の問い直しと安全の基準は上のとおり)。評価ハーネスで測って、次の 2 つを足しました。

- 語の代わりに説明を書いてきた直し (「no error」「note: …」、かっこ書き、元の語の 3 倍より長いもの) は捨てます。
- 近くに同じ文が無く、定番の誤認識でもない「削除」の提案は出しません (小さなモデルは、ふつうの文をよく「話していない文」と言います)。

### 評価ハーネス

「良くなったか」を、勘ではなく数で確かめるための仕組みです。聞き間違いを仕込んだ場面 (どの行が、どう直れば正解か) を LLM に監査させ、直せた行・見逃した行・**正しい行を壊した数**・不要な提案の数を数えます。場面は `Tests/Fixtures/llm-eval/seed.json` (英語 6・日本語 6 場面、誤りのある行 14・正しい行 36) にあり、自分の場面を足せます。

```bash
build/Kikimimi.app/Contents/MacOS/Kikimimi --eval-llm ~/Library/Application\ Support/Kikimimi/Models/LLM/qwen3.5-2b.gguf --set Tests/Fixtures/llm-eval/seed.json --report build/eval-2b.json
```

`--baseline <前の結果.json>` を付けると前の結果と比べ、悪くなっていれば終了コード 3 で止まります (正しい行を壊した数が増えた・直せた行が減った)。`--adapter <差分.lora.gguf>` で追加学習の差分を重ね、`--ledger <台帳.json>` で学習した直しを使い、`--rules-only` で LLM なしの規則だけを測ります。

本物の Qwen3.5 (Q4_K_M) を Linux の CPU で測った結果 (誤りのある行 14):

| LLM | 自動で直せた | 提案で見つけた | 見逃した | 正しい行を壊した | 不要な提案 |
|---|---|---|---|---|---|
| 2B (関門を足す前) | 3 | 4 | 7 | 0 | 13 |
| 2B (関門を足した後) | 4 | 3 | 7 | 0 | 1 |
| 4B | 5 | 2 | 7 | 0 | 3 |

- 関門で、2B の不要な提案が 13 → 1 に減りました。正しい行を壊した例は、どのモデルでも 0 です。
- 見逃した 7 行は、どちらも実在する語の取り違えで、文脈だけが頼りのものです (機会 / 機械、公園 / 講演、以上 / 異常、保障 / 保証、break / brake、Their / They're など)。小さな LLM の限界で、ここは「学習した直し」と追加学習で補います。

### 追加学習 (LoRA)

学習した直しがたまったら、LLM そのものに覚えさせることができます。元の LLM は書き換えず、小さな「差分」(LoRA アダプタ、数十 MB) を作って重ねます。学習も Mac の中だけで行います。

1. 設定の「監査・翻訳」の「学習用のデータを書き出す…」で、`kikimimi-training.jsonl` を書き出します。中身は、監査役と評価役が実際に受け取るのと同じ形の問いと、あなたの決定に沿った答えです (反映した直しは「直す」、元に戻した直しは「直さない」、何も指摘しなかった行は「そのまま」)。
2. 学習の道具を入れます (Apple シリコンの Mac。Apple の MLX を使います)。

   ```bash
   python3 -m venv .venv-finetune
   ```

   ```bash
   .venv-finetune/bin/pip install "mlx-lm[train]" gguf numpy
   ```

3. 学習します。学習 → GGUF への変換 → 評価ハーネスでの比較 (差分なしと、学習の途中の差分 5 つ) までを続けて行い、いちばん良いものが **差分なしより良くなっていれば** (直せた行が増え、誤った直しや正しい行を壊すことが増えていなければ)、ききみみの差分の置き場所に入れます。評価には、ききみみに付いている場面と、学習データから取り分けた自分の直しの場面 (学習に使っていない並び) を使います。効き目を確かめられない差分・悪くなる差分は入れません。

   ```bash
   .venv-finetune/bin/python tools/finetune/finetune.py --data ~/Desktop/kikimimi-training.jsonl --model qwen3.5-2b --install
   ```

4. 設定の「監査・翻訳」の「追加学習 (LoRA)」で、使う / 使わないを選べます。「外す」で元の LLM だけに戻ります。別の場所で作った差分は「差分を追加…」で入れられます (選んでいる LLM の種類・大きさと合わないものは断ります。読み込めなかったときは、差分なしで動かして知らせます)。

知っておいてほしいこと:

- **必要なメモリの目安**: 2B の学習に 8 GB、4B に 16 GB、9B に 32 GB。8 GB の Mac では 2B を使ってください (足りないときは止めて知らせます)。初回は、学習用のモデル (MLX 形式、`mlx-community/Qwen3.5-2B-4bit` など) を Hugging Face から取得します。
- **学習データは 12 件以上** 必要です。数件の直しなら、追加学習をしなくても「学習した直し」がそのまま当てます。追加学習が効くのは、直しが数十件たまり、覚えた語そのものではない似た場面にも広げたいときです。
- **学習の量と、差分の選び方**: 既定では、学習データを 5 周します (300〜1000 回。学習率は少しずつ下げます)。何回がよいかは決め打ちできないので、途中の差分を 5 つ残し、評価ハーネスでいちばん良いものを選びます。Qwen3.5 0.8B と 12 件の直し (学習例 90 件) で確かめた例 (誤りのある行 24 と、翻訳の場面 3。どれも学習に使っていない文):

  | | 直せた行 (うち自動) | 誤った直し | 正しい行を壊した数 | 不要な提案 | 翻訳で保てた固有名詞 |
  |---|---|---|---|---|---|
  | 差分なし | 3 (2) | 0 | 0 | 5 | 2/2 |
  | 100 回 | 2 (2) | 0 | 0 | 1 | 1/2 |
  | 200 回 | 12 (11) | 0 | 0 | 1 | 2/2 |
  | 300 回 | 14 (14) | 0 | 0 | 1 | 1/2 |
  | 400 回 | 14 (14) | 0 | 0 | 1 | 1/2 |

  直せる行は 300 回・400 回が最多ですが、翻訳で「Roblox Studio」が「ロブス・スタジオ」になる副作用が出たので、評価ハーネスは「悪くなっている」と判定し、翻訳を壊さない 200 回の差分を選びます。学習率を下げずに 600 回まで続けた別の実験では、500 回以降は逆にほとんど直さなくなり (2 行)、別の種では「Roblocks → Robo」という誤った直しも出ました。小さなモデルの追加学習はこのように不安定なので、必ず評価を通してから使ってください (スクリプトは自動でそうします)。上の数字は、同じ学習を PyTorch で行い、変換した差分を llama.cpp で評価したものです。
- スクリプトは、mlx-lm をそのまま使うと学習が効かなくなる 3 点を直しています (どれも、同じ学習を PyTorch で再現して確かめました)。
  - **学習の範囲**: mlx-lm は、答えの前の「考える部分を閉じる印」まで学習の対象にします。Qwen3.5 では学習のほとんどがそこに使われるので、答えだけを対象にします。
  - **損失の計算**: mlx-lm は、学習例の終わりの詰め物 1 つまで損失に数えます。答えだけ (3〜12 語) を学習すると、その 1 つが損失の大半になるので (ある例で 4.634 対 0.012)、数えないようにします。
  - **最適化**: MLX の Adam は、既定で偏りの補正をしません。最初の数百回は約 3 倍の大きさで重みが動き、学習率 2e-4 では不安定になるので (検証の損失が 0.36 → 1.15 → 1.78)、補正を有効にします。
- **差分は、学習に使った LLM 専用** です (2B で作った差分は 4B では使えません)。LLM を替えたら、学習し直してください。
- 学習するのは各層の MLP だけです (Qwen3.5 は注意機構と状態空間モデルの混成で、MLP の重みだけが MLX と GGUF で 1 対 1 に対応します)。変換は `tools/finetune/mlx_lora_to_gguf.py` が行います。

## 設定 (⌘,)

- **精度を優先する**: ビームサーチで認識します。オフにすると速くなります。
- **無音を飛ばす (VAD)**: 無音部分を飛ばして処理を速くし、無音での誤認識を減らします (VAD モデル約 0.9 MB を自動取得)。
- **日本語と英語が混ざっている録音は、自動で「日本語＋英語」で文字にする** (既定でオン): 言語が「日本語」「英語」「自動判定」のとき、文字にする前に、録音全体から均等に選んだ区切り (発話 3 秒以上、最大 24 個) の言語を確かめます。もう一方の言語がある区切り (多い側でない言語の確率が 0.25 以上。日本語と英語が入っていて判定が確かでない区切りも数えます) が 2 個以上、かつ判定できた区切りの 10% 以上あれば、「日本語＋英語」で文字にします (候補は設定の言語が先。結果は「日本語＋英語」を選んだときと同じ)。1 つの言語だけの録音は、確かめる数秒〜数十秒のほかは今までと同じ結果です。VAD が使えないときと、確かめられる区切りが 4 つ未満の短い録音では確かめません。
- **定番の誤認識と、同じ文の繰り返しを取り除く**: 無音や BGM のところで Whisper が出しがちな「ご視聴ありがとうございました」などを、発話が無さそうなときだけ取り除きます。間を空けずに同じ文が 4 回以上 (2〜3 文の組なら 3 周以上) 続いたときは最初の 1 回だけ残し、1 文の中で同じ語句が 6 回以上続くときも 1 回にまとめます。数分おきに同じことを言う場面や、「No, no, no, no, no.」のような強調、金額・番号は残します。
- **語彙のヒント**: 固有名詞や専門用語 (例: Roblox Studio, ロブロックス) を書いておくと、その表記で出やすくなります。監査と翻訳でも使います。
- **監査・翻訳 (ローカル LLM)**: 「監査・翻訳」タブで、文字起こしのあとに自動で監査するか、日本語以外の区間を自動で訳すか、どの LLM を使うかを選べます。LLM の取得・削除・取り込みもここで行います。
- **学習した直し / 追加学習 (LoRA)**: 同じタブで、覚えた直しの一覧・削除・追加、学習用のデータの書き出し、追加学習の差分を入れる・外す・使う、を行います。

## うまくいかないとき

- **モデルのダウンロードが失敗する**: Hugging Face (huggingface.co) に接続できる必要があります。会社のネットワーク等で繋がらない場合は、別の環境で次のファイルを入手し、設定の「手元のファイルを追加…」で取り込めます。
  - 音声認識モデル: `ggml-large-v3-turbo-q5_0.bin` (huggingface.co/ggerganov/whisper.cpp)
  - 無音検出 (VAD) モデル: `ggml-silero-v6.2.0.bin` (huggingface.co/ggml-org/whisper-vad)。無くても動きます。取れなかったときは 10 分おきに取り直します。
- **LLM のダウンロードが失敗する**: 音声認識モデルと同じく Hugging Face に接続できる必要があります。繋がらない場合は、別の環境で Qwen3.5 の GGUF (例: huggingface.co/unsloth/Qwen3.5-4B-GGUF の `Qwen3.5-4B-Q4_K_M.gguf`) を入手し、設定の「手元の GGUF を追加…」で取り込めます。
- **翻訳が遅い / Mac が重くなる**: 設定で LLM を「Qwen3.5 2B (軽量)」に替えてください。翻訳は「中止」でいつでも止められ、訳せた所までは残ります。「残りを翻訳」で続きから訳せます。
- **監査の直しが気に入らない**: 「監査: …」の一覧で、その直しのチェックを外すと元に戻ります。「すべて元に戻す」もあります。
- **起動しない / ウインドウが出ない**: 次を実行すると、環境・組み立てたアプリ・起動の確認・クラッシュの記録を `build/doctor.txt` にまとめます (途中でウインドウが出て、数秒で自動的に閉じます)。その内容をそのまま報告してください。

  ```bash
  make doctor
  ```

  ウインドウを閉じたまま動いているとき (文字起こしや翻訳の途中、または書き出していない文字起こしが残っているとき) は、Dock のアイコンを押すか、メニューの「ファイル > メインウインドウを表示」(⌘0) で開き直せます。作業中でなく、結果もすべて書き出して (またはコピーして) あれば、ウインドウを閉じるとアプリも終了します。ききみみは文字起こしの結果をファイルに保存しないので、書き出していない結果があるときに終了 (⌘Q) しようとすると、確かめます。
- **`make run` で whisper.framework / llama.framework が見つからないと言われる**: 次を実行してから、もう一度 `make run` してください。

  ```bash
  swift package reset
  ```

- **マイク許可のダイアログが出ない / 拒否してしまった**: システム設定 › プライバシーとセキュリティ › マイク で「ききみみ」をオンにします。作り直して署名が変わった場合は、次を実行してから起動し直してください。

  ```bash
  tccutil reset Microphone local.kikimimi.app
  ```

- **録音中に AirPods をつないだ / 入力を切り替えた**: 新しい入力で録音を続けます。続けられなかったときは、そこまでの録音を文字起こしします。
- **同じ文が延々と繰り返される (1.0.0 の不具合)**: 1.0.0 では、30 秒ごとの区間で認識した文章を次の区間の手がかりとして渡していたため、音楽や雑音で一度誤認識すると、その文が後ろの区間すべてに連鎖しました。1.0.1 で直しています。1.0.0 で文字起こししたファイルは、失われた部分を取り戻すために、もう一度文字起こししてください。
- **webm / mkv / ogg が読めない**: AVFoundation が対応していない形式です。QuickTime Player か ffmpeg で m4a / mp4 に変換してから使ってください。
- **起動時に「開発元を確認できない」と出る**: 自分でビルドしたアプリは通常出ませんが、出た場合は Finder でアプリを右クリック › 開く を選んでください。

## テスト

書き出し・モデル一覧・WAV・誤認識フィルタ・監査・翻訳など UI に依存しない部分は `KikimimiCore` に分けてあり、テストできます。

```bash
swift test
```

組み立てたアプリで文字起こしを動かす診断もあります (画面は出ません)。区切りごとの言語の判定・文字にした範囲・点検で引っかかったところと直し・区間ごとの言語・かかった時間・使ったメモリを表示します。モデルと VAD は、指定が無ければアプリで取得したものを使います。`--from` / `--to` (秒) で一部だけ、`--languages ja` で「日本語」の設定、`--auto-mixed` で (`--languages ja` などと一緒に) 日本語と英語が混ざっているかを先に確かめる設定 (確かめた区切りと結果を表示します)、`--report` で結果を JSON に書き出します。

## 設計メモ

- **whisper.cpp を選んだ理由**: macOS 14 で動き、Metal で速く、ビルド済みの公式 XCFramework があるので C/C++ のビルドが不要です。日本語の精度は OpenAI Whisper と同じモデルなので同等です。
- **macOS 26 の SpeechAnalyzer** は将来の選択肢です。macOS 26 に上げた場合は、エンジンを差し替えられる構成にしてあります。
- **長い音声と繰り返しの暴走**: Whisper は 30 秒ずつ処理します。whisper.cpp の既定では、直前の区間で認識した文章を次の区間の手がかりとして渡します。`no_context` はこれを止めません (前回の呼び出しの文脈を捨てるだけです)。そこで `n_max_text_ctx = 0` にして区間どうしの引き継ぎを止め、OpenAI 版の `condition_on_previous_text=False` と同じ動きにしています。語彙のヒントは `carry_initial_prompt` で毎区間に付け、`n_max_text_ctx` を「ヒントのトークン数 + 1」に絞って、前の区間の文章が入らないようにしています。区間内で繰り返しになったときの言い直しは、ビームサーチでも 5 候補から選びます (`greedy.best_of = 5`、whisper-cli と同じ。既定のままだと 1 候補だけの抽選になります)。繰り返しとみなす基準 (`entropy_thold`) は既定の 2.4 のままです。上げると普通の発話でも言い直しが増えて遅くなり、音楽部分のでたらめな文もかえって片付けにくくなることを、再現実験で確かめました。それでも残った分は後始末で片付けます。
- **監査と翻訳にローカル LLM を選んだ理由**: 無料で、音声の内容を外へ出さずに済み、オフラインでも動くからです。llama.cpp は Metal で速く、ビルド済みの公式 XCFramework があります。小さなモデルでも形が崩れないよう、出力は GBNF 文法で「番号・行数」まで縛り、1 行が長すぎたら打ち切ります (同じ語を延々と出す暴走の歯止め)。答えは貪欲法で決めるので、同じ入力には同じ答えを返します。
- **whisper.cpp と llama.cpp の同居**: 2 つのフレームワークは、版の違う ggml.h をそれぞれ持っています。Swift で両方の C モジュールを 1 つのコンパイルに入れると型の定義がぶつかるので、C モジュールは各ラッパーの中だけで使い (`internal import`)、ラッパーと KikimimiCore を library evolution でビルドして、アプリ本体のコンパイルに持ち込まないようにしています。実行時の記号の重なりも確かめてあります (互いに呼び合うことはありません)。
- **日本語＋英語**: whisper は 30 秒ずつ、1 つの言語の指定 (`<|ja|>` など) で文字にします。VAD は間を 0.1 秒に詰めるので、英語と日本語が入れ替わる録音では、1 つの 30 秒に両方の言語が入ります。日本語の指定で英語を聞くと「彼は、彼は、…」のような繰り返しになり、それを後始末で縮めたものが、英語の中に 1 行だけ残る崩れた日本語の正体でした (英日を交互に並べた録音で再現。誤りは 25%)。自動判定も、最初の 30 秒で 1 回決めるだけなので役に立ちません。「日本語＋英語」では、VAD で見つけた発話を 28 秒以内の区切りにまとめ、区切りごとに whisper の言語判定を日本語と英語の 2 つだけで比べます (候補を絞らないと、短い音声で中国語や韓国語を作り出します)。判定が揺れる区切りは、中の長い間で分けて判定し直し、間を空けずに入れ替わるところは 4 秒・2 秒の窓の二分探索で探します (話し声が 1 秒に満たない窓は、無音に近い判定が当てにならないので、1 秒話すところまで広げてから判定します)。確からしさの高い区切りでも、別の言語の確率がそのファイルのふつう (英語の区切りの中央値の 5 倍) より高ければ、区切りを半分ずつにして、中ほどに挟まった短い別の言語 (島) を探します。英語で文字にすると、日本語の一言は訳されずに消え、点検にも何も残らないためです。雑音で全体に広がった揺れは、両端の窓や最初に分けた半分どうしを比べて見分け、探しません。同じ言語の区切りをつないで (最長 10 分)、今の「日本語」と同じ設定でその言語で文字にし、繰り返し・自信の低さ・話した長さに合わない文字の量・抜けを安く点検します。引っかかったところは判定し直し (確からしさが低ければ、先に切り替わりと島を探します)、別の言語の部分を、重なる元の区間の全体まで広げてその言語で文字にし直し、良くなったときだけ入れ替えます (同じ言語なら元のまま。文字にし直して何も出なければ、元の文を残します。点検は文を消しません)。数値は、英日の朗読 (FLEURS) と日本語の講演で測って決めました。
  「日本語」「英語」「自動判定」でも、文字にする前に同じ VAD と区切りを作り、録音全体から均等に選んだ区切り (発話 3 秒以上、最大 24 個) を日本語と英語の 2 つだけで判定します。判定の確率の合計が多い側を多い側の言語とし、もう一方の言語の確率が 0.25 以上の区切り (もう一方の言語と判定された区切りと、判定が確かでない区切り) が 2 個以上、かつ判定できた区切りの 10% 以上なら、「日本語＋英語」で文字にします。通訳が短く交代する講演では、ほとんどの区切りに両方の言語が入って判定が確かでなくなるので、確かでない区切りも混ざっている証として数えます (1 つの言語だけの録音では、区切りの判定は 0.977 以上でした) (このとき、確かめたときの VAD と判定を使い回します)。混ざっていなければ、今までと同じ 1 つの言語の文字起こしです。2 時間の講演 (英語の講師と日本語の通訳) を「日本語」のまま文字にすると英語の部分が崩れたため、選び直さなくても済むようにしました。
- **ファインチューニングよりハーネスが先**: 小さな LLM の弱点 (何でも直したがる・説明を書いてくる・同じ誤りを何度もする) の多くは、重みを変えなくても、まわりの仕組みで止められます。そこで、(1) 利用者の決定を覚えて機械的に当てる台帳、(2) 答えを反映する前の関門、(3) 変更の前後を同じ場面で比べる評価ハーネス、を先に作りました。台帳は 1 件目から確実に効き、学習の時間もメモリも要りません。追加学習 (LoRA) は、直しが数十件たまってから、評価ハーネスで「悪くなっていない」と確かめられたときだけ使う位置づけです。
- **署名**: ad-hoc 署名です。人に配る場合は Developer ID での署名と公証に差し替えてください。

## 既知の制限

- 話者分離はありません。「日本語＋英語」は声ではなく、話している言語で区切ります。
- 「日本語＋英語」でも、間を空けずに入れ替わるところでは前後 1.5 秒ほどが抜けることがあります。1.5 秒より短い差し込み (相づちなど) や、雑音の多い録音の中の差し込みは、見つからずに前後の言語で文字になったり抜けたりすることがあります。
- 自動判定は最初の 30 秒で言語を 1 回決めるだけです。日本語と英語なら、混ざっているかを先に確かめて「日本語＋英語」に切り替えます (設定でオンのとき) が、英語の中の短い日本語の一言 (3 秒未満) だけの録音は「混ざっていない」と判定されやすいので、一言も拾いたいときは「日本語＋英語」を選んでください。
- 翻訳は日本語への一方向だけです。
- 「日本語＋英語」は、「無音を飛ばす (VAD)」をオンにして使ってください (既定)。オフだと、無音のところの言語の判定が当てにならず、無い切り替わりを作って数秒を別の言語で文字にすることがあります。
- 監査の「学習した直し」は、語の置き換えです。同じ語が、ある行では誤りで別の行では正しい、という直し (同音の語の取り違えなど) は、1 回の反映では提案どまりにしてありますが、2 回反映すると自動になります。合わなくなったら、設定の「学習した直し」から削除してください。
- 録音中のプレビューは直近 12 秒ぶんだけです (止めると全体を認識し直します)。
